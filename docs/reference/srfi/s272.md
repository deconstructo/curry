# `(srfi 272 ...)` — SRFI-272 Pretty Printing

```scheme
(import (srfi 272))              ; minimalist: just `pp`
(import (srfi 272 basic))        ; + pp-width/pp-graph/pp-circle, pprint/pprint-shared/pprint-simple
(import (srfi 272 intermediate)) ; + keyword args, pp*, pprint-file, pretty-style
(import (srfi 272 advanced))     ; + full parameter set, hooks, styles, make-pprint-generator
(import (srfi 272 fancy))        ; + comment-preserving pprint-file, pprint-file/html
(import (srfi 272 colorize))     ; ANSI SGR color generation, independent of the tiers above
(import (srfi 272 measure))      ; char-width-procedure, independent of everything above
```

Every library above is also importable as `(srfi srfi-272 ...)` (e.g. `(srfi srfi-272 basic)`), the alternate-naming convention this codebase uses throughout.

[SRFI-272](https://srfi.schemers.org/srfi-272/) is a **Draft** SRFI (draft #3, 2026-09-21) defining a layered pretty-printer: five tiers of increasing capability sharing one `pp`-shaped core, plus three independent utility libraries. Implemented in full here at explicit user request despite Draft status — every other Draft/Withdrawn SRFI encountered so far this session was skipped or scoped down instead; this is the one deliberate exception.

```scheme
(import (scheme base) (srfi 272))
(pp '(define (fib n) (if (< n 2) n (+ (fib (- n 1)) (fib (- n 2))))))
```

## Scope decisions

Because the spec is still a Draft and leaves several mechanisms to "an implementation may" prose rather than a precise algorithm, this port made a number of concrete, documented choices rather than inventing an undocumented one-off design:

- **`(srfi 272 show)` is not implemented.** It depends on SRFI-166 (Monadic Formatting), which curry does not have — the same "declare the gap, don't fake it" precedent as `(srfi 225)` omitting SRFI-146/167 support earlier this session.
- **The layout engine is a real, from-scratch implementation** of the well-known two-pass simplification of Wadler's "A Prettier Printer" algorithm (measure a group's flat width; if it fits the remaining column budget, print it flat, otherwise break each child onto its own line) — not a line-by-line port of any one reference implementation, and not a naive "just call `write`" stand-in.
- **Two independent sharing/cycle scans**, both eq?-hash-table-based: one counts total visits per object to find every object occurring more than once (`graph` mode, matching `write-shared`); the other does a DFS with on-stack/done marking to find only genuine cycles (`circle` mode, matching `write`). `simple` mode runs neither scan and can loop forever on circular input, exactly as the spec's own text warns `pprint-simple`/`write-simple` may.
- **`(srfi 272 measure)`'s `char-width-procedure`** uses a practical, non-exhaustive approximation of Unicode East Asian Width (representative Wide/Fullwidth and combining-mark block ranges, C0/C1 controls scored `#f`, everything else width 1) rather than the full UAX #11 property tables, which curry does not bundle. It also is **not** wired into the core engine's own column-width tracking (which counts codepoints via plain `string-length`) — it's provided as a standalone, spec-conformant utility for a caller's own use, not silently claimed as integrated where it isn't.
- **The fancy tier's enhanced `pprint-file`** finds top-level form boundaries with a hand-written balanced-delimiter scanner over raw source text (parens/brackets, string and character literals, `;` line comments, `#|...|#` block comments) rather than asking the reader for a source span, which curry's `read` doesn't expose. Blank lines and comment-only lines between forms are preserved verbatim; a trailing same-line comment is not (there's nowhere to reattach it once the datum is parsed and reprinted). Its "Local Variables:" recognition is narrowed to `pp-style: SYMBOL STYLE` lines specifically, a deliberately concrete reading of the spec's own vaguer "recognizes ... style comments for custom formatting rules."
- **`pprint-file`/`pprint-file/html`'s `outfile` argument** accepts an already-open output port directly, in addition to the spec's own filename-string form — a harmless superset consistent with how `pp`/`pprint` already accept a port, useful for testing and for callers who already have a port in hand.

## The five `pp`-shaped tiers

Each tier after the minimalist one adds capability without breaking the shape of what came before, but tiers are **not** drop-in compatible with each other: `(srfi 272 basic)`'s `pp` takes only `(pp obj [port])`, while `(srfi 272 intermediate)`'s `pp` additionally accepts trailing keyword arguments — import only the one tier you need.

| Tier | `pp` signature | Adds |
|---|---|---|
| `(srfi 272)` | `(pp obj [port])` | Just `pp`, fixed internal defaults. |
| `(srfi 272 basic)` | `(pp obj [port])` | `pp-width`/`pp-graph`/`pp-circle` parameters; `pprint`/`pprint-shared`/`pprint-simple` (hardwired to `write`/`write-shared`/`write-simple` sharing semantics regardless of `pp-graph`/`pp-circle`). |
| `(srfi 272 intermediate)` | `(pp obj [port] [key value] ...)` | `pp*` (splices a trailing kv-list); `pprint-file`; `pp-radix`/`pp-level`/`pp-length`; `pretty-style` get/setter. |
| `(srfi 272 advanced)` | same | Every other parameter (`pp-lines`, `pp-miser-width`, `pp-indent`, `pp-emit`, `pp-tint`, ...); the style and hook registries (`add-pp-style`/`lookup-pp-style`, `add-pp-hook`/`lookup-pp-hook`); the four hook constructors (`glst-pp-hook`, `bvec-pp-hook`, `atom-pp-hook`, `rmac-pp-hook`); `make-pprint-generator`. |
| `(srfi 272 fancy)` | same | Everything from advanced, plus a `pprint-file` that preserves comments/blank lines and reads `pp-style:` local-variable hints, and `pprint-file/html`. |

`pp`'s own sharing mode is chosen from `pp-graph`/`pp-circle` (`pp-graph` wins if both are true; otherwise `pp-circle`; otherwise plain, unscanned printing). `pprint`/`pprint-shared`/`pprint-simple` ignore those two parameters entirely and always use `write`/`write-shared`/`write-simple` semantics respectively — from `(srfi 272 intermediate)` onward, keyword arguments for `pp-graph`/`pp-circle` are likewise silently dropped for these three, per the spec's own precedence rule.

```scheme
(import (scheme base) (srfi 272 intermediate))
(pp '(1 2 3 4 5) (current-output-port) 'pp-width 3)
;; (1
;;  2
;;  3
;;  4
;;  5)
```

### Custom object rendering: hooks

A hook lets `pp` render an arbitrary object type as if it were built-in syntax. `glst-pp-hook` treats an object as a generalized list (a prefix, a conversion to an ordinary list, and a suffix):

```scheme
(import (scheme base) (srfi 272 advanced))
(define-record-type <point> (make-point x y) point? (x point-x) (y point-y))
(parameterize ((pp-hooks (add-pp-hook (pp-hooks) point?
                           (glst-pp-hook "#[point " (lambda (p) (list (point-x p) (point-y p))) #f "]"))))
  (pp (make-point 1 2)))
;; #[point 1 2]
```

`atom-pp-hook` instead treats the object as indivisible (an exact printed width plus a display procedure); `bvec-pp-hook` treats it as a binary-vector-shaped sequence; `rmac-pp-hook` treats it as read-macro sugar like `'x` for `(quote x)`. A hook-registry test procedure may itself return the hook to use (registered by associating it with `#t` rather than a hook object) — useful when which hook applies depends on the object, not just its type.

## `(srfi 272 colorize)`

ANSI SGR ("Select Graphic Rendition") escape-sequence generation across four fidelity tiers — `sgr0` (16-color), `sgr1` (256-color), `sgr2` (24-bit truecolor), `sgr3` (truecolor plus extended attributes: dim, extended underline styles). `detect-sgr-tier` probes `TERM`/`COLORTERM`/`NO_COLOR`/`CLICOLOR_FORCE`; `sgr-support-tier` holds the (overridable) result. An **ASB** (ANSI SGR Bundle) bundles one parameter string per tier so a single color choice degrades gracefully on a less-capable terminal; a **palette** maps 16 indices to ASBs, and a **semantic color mapper** maps semantic categories (`comment`, `string`, `keyword`, ...) to palette entries.

```scheme
(import (scheme base) (srfi 272 colorize))
(display (semantic-color->start-string 'comment)) (display "; a comment")
(display (semantic-color->end-string 'comment))
```

`sgr3`'s `uline` argument accepts `#t`/`straight`, `double`, `curly`, `dotted`, `dashed` (or the numeric/character shorthand the spec lists), and a `(style . rgb)` pair for a colored underline, using the widely-deployed (if non-standard) `4:N`/`58;2;r;g;b` sequences several modern terminals already support.

## `(srfi 272 measure)`

```scheme
(import (scheme base) (srfi 272 measure))
((char-width-procedure) #\a)              ; => 1
((char-width-procedure) (integer->char #x4e2d)) ; => 2 (a CJK ideograph)
```

A single parameter, `char-width-procedure`, holding a `(char) -> (0|1|2|#f)` terminal-column-width function — see the Scope decisions section above for the extent of this implementation's Unicode coverage.
