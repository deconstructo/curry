# `(srfi 272 ...)` — SRFI-272 Pretty Printing

```scheme
(import (srfi 272))              ; minimalist: just `pp`
(import (srfi 272 basic))        ; + pp-width/pp-graph/pp-circle, pprint/pprint-shared/pprint-simple
(import (srfi 272 intermediate)) ; + keyword args, pp*, pprint-file, pretty-style
(import (srfi 272 advanced))     ; + full parameter set, hooks, styles, make-pprint-generator
(import (srfi 272 fancy))        ; + comment-preserving pprint-file, pprint-file/html
(import (srfi 272 colorize))     ; ANSI SGR color generation, independent of the tiers above
(import (srfi 272 measure))      ; char-width-procedure, independent of everything above
```

Every library above is also importable as `(srfi srfi-272 ...)` (e.g. `(srfi srfi-272 basic)`), the alternate-naming convention this codebase uses throughout.

[SRFI-272](https://srfi.schemers.org/srfi-272/) (Pretty Printing, Sergei Egorov) is **Final** (2026-11-01). It defines a layered pretty printer: five tiers of growing capability that share one `pp`-shaped core, plus three independent libraries. This port follows the final text.

```scheme
(import (scheme base) (srfi 272))
(pp '(define (fib n) (if (< n 2) n (+ (fib (- n 1)) (fib (- n 2))))))
```

## How the layout works

`pp` builds a tree from the datum, then lays it out. A form that fits in the remaining width prints on one line. The closing parentheses that must follow it on that line count toward the width. A form that does not fit is broken according to its **style**:

- **Styled forms.** If the form's head is a symbol that has an entry in `pp-styles`, the style says how to break it. A style is `(_ . format)`. The codes before the tail name *distinguished arguments* that stay on the head line (`i` identifier, `d` datum, `e` expression, `f` formals, `l` literals, `h` definition head, `dc ec fc lc` one clause, `dc* ec* fc* lc*` a list of clauses). The tail lays out the remaining arguments: `body` puts each on its own line, indented by `pp-tab` + 1 from the open parenthesis; `fill` packs as many as fit per line; `dc* ec* fc* lc*` lines them up as clauses. `i?` takes an identifier if one is there and is skipped if not (this is how named `let` works).
- **Applications.** A form with any other symbol head prints as a procedure call: the arguments line up under the first one, or are indented by `pp-tab` when the head is longer than `pp-max-tab` or the line is within `pp-miser-width` of the margin.
- **Data.** Any other list, a vector, or any list when `pp-code` is false prints one element per line, lined up after the open parenthesis.

`pp-styles` starts with styles for the R7RS special forms (`define`, `lambda`, `let` and the other `let` forms, `if`, `when`, `unless`, `begin`, `and`, `or`, `do`, `cond`, `case`, `guard`, `case-lambda`, `parameterize`, and a few more). Add your own with `add-pp-style` or `pretty-style`. `pp-code` is true by default; set it to false to print everything as data.

Read macros print in their short forms: `(quote x)` as `'x`, and likewise for `quasiquote`, `unquote` and `unquote-splicing`.

A form with a single argument keeps that argument on its head line, so a deeply nested chain of one-argument forms can run past the margin. That is a limit of the layout, not of the width setting.

## Unicode, UTF-8 and cuneiform

All widths are measured in terminal columns, not code points. The width table comes from the Unicode Character Database 16.0.0 (`tools/gen-width-table.py` writes `lib/curry/modules/srfi/s272/width-data.scm`):

- East Asian Wide and Fullwidth characters, and characters with emoji presentation, take 2 columns.
- Combining marks, zero-width joiners, variation selectors and tag characters take 0.
- A ZWJ sequence, a flag made of two regional indicators, and an emoji with a skin-tone modifier take the columns of one glyph. Variation selector 16 widens a symbol that is narrow by default (for example the heart U+2764) to 2.
- **Cuneiform signs are East Asian Width Neutral, so each takes 1 column.** The Akkadian transliteration letters (`š ṭ ḫ ā ī`) take 1 each, whether precomposed or written as a base letter plus a combining mark.

Strings and symbols are written as they are, so cuneiform and Akkadian text is not escaped. `pprint-file` reads and writes UTF-8.

A form headed by an Akkadian or cuneiform special-form name is laid out with the style of its English name, because the head is passed through `lang-translate` first: `(šakānum (f n) ...)` and `(𒁹 (f n) ...)` print like `(define (f n) ...)`.

One limit comes from curry's reader (issue #354): numerals written in cuneiform and separated by spaces inside a list read back as one number, so a list of cuneiform numerals cannot be read back from `pp` output. `pprint-file` is not affected, because it keeps the text of each token as written and never re-reads it.

## Scope decisions

- **`(srfi 272 show)`** needs SRFI 166. See the `show` section below for its status.
- **Layout algorithm.** A two-pass fit-or-break layout, not a transliteration of any reference implementation. The result may differ from other implementations in where it breaks; it always reads back equal for data that curry's reader can read back.
- **`pp-lines-stub`.** When `pp-lines` cuts the output, the stub follows the last kept line. The closing parentheses of the forms that were cut are not added after it.
- **`pp-indent`.** Defaults to 0. It is not taken from the current column of the port.
- **`pp-hooks`.** `atom-pp-hook` ignores its width procedure and measures the strings its display procedure returns.
- **`pprint-file` and `pp-radix`/`pp-hooks`.** With `pp-decorate` true the file is parsed by the library itself so that comments survive, and atoms keep their source text. `pp-level` and `pp-length` still apply; `pp-radix` and `pp-hooks` do not.
- **`outfile`.** `pprint-file` and `pprint-file/html` accept an output port as well as a file name.

## The five `pp`-shaped tiers

Each tier adds capability to the one before it, but the tiers are **not** drop-in compatible: `(srfi 272 basic)`'s `pp` takes only `(pp obj [port])`, while `(srfi 272 intermediate)`'s `pp` also accepts trailing keyword arguments. Import one tier at a time, or use prefixes.

| Tier | `pp` signature | Adds |
|---|---|---|
| `(srfi 272)` | `(pp obj [port])` | Just `pp`. |
| `(srfi 272 basic)` | `(pp obj [port])` | `pp-width`, `pp-graph`, `pp-circle`; `pprint`, `pprint-shared`, `pprint-simple`. |
| `(srfi 272 intermediate)` | `(pp obj [port] [key value] ...)` | `pp*` (splices a trailing key/value list); `pprint-file`; `pp-radix`, `pp-level`, `pp-length`; `pretty-style`. |
| `(srfi 272 advanced)` | same | The rest of the parameters (`pp-lines`, the stubs, `pp-miser-width`, `pp-indent`, `pp-tab`, `pp-code`, `pp-brackets`, `pp-pretty`, `pp-color`, `pp-emit`, `pp-tint`, ...); style and hook registries; the four hook constructors; `make-pprint-generator`. |
| `(srfi 272 fancy)` | same | A `pprint-file` that keeps comments and reads file-local settings, and `pprint-file/html`. |

`pp` picks its sharing mode from `pp-graph` and `pp-circle` (`pp-graph` wins if both are true; with both false it prints without checking for sharing). `pprint`, `pprint-shared` and `pprint-simple` ignore those two parameters and behave like `write`, `write-shared` and `write-simple`.

```scheme
(import (scheme base) (srfi 272 intermediate))
(pp '(1 2 3 4 5) (current-output-port) 'pp-width 3)
;; (1
;;  2
;;  3
;;  4
;;  5)
```

Keyword arguments are scanned left to right; the leftmost one for a parameter wins. Unknown keywords are ignored. A parameter object may be used in place of its keyword symbol.

### Files: `(srfi 272 fancy)`

`pprint-file` with `pp-decorate` true (the default) keeps the comments of the file, including comments inside forms, and the blank lines between forms (at most two in a row). A comment at the end of an element's line stays on that line; a list that holds a comment is always broken, because a line comment cannot sit on a line with more code after it. Block comments (`#| |#`) and datum comments (`#;`) are kept too. With `pp-decorate` false, comments are dropped and forms are separated by one blank line.

Settings can come from the file itself:

```scheme
#!/usr/bin/env curry
;;; -*- mode: scheme; fill-column: 80; pp-tab: 2 -*-
;; * pp-styles: my-let := let; my-form := (_ e . body)
```

- The first `-*- key: value; ... -*-` in the header (the leading blank, comment and `#!` lines) sets parameters. `pp-width` and `fill-column` set `pp-width`; `pp-inline-width`, `pp-miser-width`, `pp-tab`, `pp-max-tab` and `pp-brackets` set the parameter of the same name. Values are numbers, `t` or `nil`. These settings replace the current value of the parameter, and keyword arguments to `pprint-file` replace them in turn.
- A top-level comment of the form `;... * pp-styles: A := B; C := (_ ...)` changes the style registry for the whole file. The right side is a symbol that already has a style, or a style starting with `_`.

`pprint-file/html` writes `<pre>...</pre>`. Text is HTML-escaped. With `pp-color` true, each token is wrapped in `<span class="pp-CATEGORY">`, where the category is one of the semantic categories listed under `colorize` (for example `pp-keyword`, `pp-string`, `pp-comment`). If `pp-color` is a procedure, that procedure is used as the mapper.

### Custom object rendering: hooks

A hook lets `pp` render an arbitrary object type as if it were built-in syntax. `glst-pp-hook` treats an object as a generalized list (a prefix, a conversion to an ordinary list, and a suffix):

```scheme
(import (scheme base) (srfi 272 advanced))
(define-record-type <point> (make-point x y) point? (x point-x) (y point-y))
(parameterize ((pp-hooks (add-pp-hook (pp-hooks) point?
                           (glst-pp-hook "#[point " (lambda (p) (list (point-x p) (point-y p))) #f "]"))))
  (pp (make-point 1 2)))
;; #[point 1 2]
```

`atom-pp-hook` instead treats the object as indivisible (an exact printed width plus a display procedure); `bvec-pp-hook` treats it as a binary-vector-shaped sequence; `rmac-pp-hook` treats it as read-macro sugar like `'x` for `(quote x)`. A hook-registry test procedure may itself return the hook to use (registered by associating it with `#t` rather than a hook object) — useful when which hook applies depends on the object, not just its type.

## `(srfi 272 colorize)`

ANSI SGR ("Select Graphic Rendition") escape-sequence generation across four fidelity tiers — `sgr0` (16-color), `sgr1` (256-color), `sgr2` (24-bit truecolor), `sgr3` (truecolor plus extended attributes: dim, extended underline styles). `detect-sgr-tier` probes `TERM`/`COLORTERM`/`NO_COLOR`/`CLICOLOR_FORCE`; `sgr-support-tier` holds the (overridable) result. An **ASB** (ANSI SGR Bundle) bundles one parameter string per tier so a single color choice degrades gracefully on a less-capable terminal; a **palette** maps 16 indices to ASBs, and a **semantic color mapper** maps semantic categories (`comment`, `string`, `keyword`, ...) to palette entries.

```scheme
(import (scheme base) (srfi 272 colorize))
(display (semantic-color->start-string 'comment)) (display "; a comment")
(display (semantic-color->end-string 'comment))
```

`sgr3`'s `uline` argument accepts `#t`/`straight`, `double`, `curly`, `dotted`, `dashed` (or the numeric/character shorthand the spec lists), and a `(style . rgb)` pair for a colored underline, using the widely-deployed (if non-standard) `4:N`/`58;2;r;g;b` sequences several modern terminals already support.

## `(srfi 272 measure)`

```scheme
(import (scheme base) (srfi 272 measure))
((char-width-procedure) #\a)                   ; => 1
((char-width-procedure) (integer->char #x4e2d)) ; => 2 (a CJK ideograph)
((char-width-procedure) (integer->char #x12000)) ; => 1 (a cuneiform sign)
((char-width-procedure) (integer->char #x0304)) ; => 0 (combining macron)
((char-width-procedure) (integer->char 7))      ; => #f (a control character)
```

One parameter, `char-width-procedure`, holds a `(char) -> (0|1|2|#f)` function. The default follows UAX #11 as described in the Unicode section above. The layout engine measures strings with it (plus the cluster rules for ZWJ sequences, flags and variation selectors), so replacing the parameter changes where lines break.
