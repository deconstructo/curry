# `(srfi s125 hash-tables)` and `(srfi s126 hashtables)` — SRFI-125 / SRFI-126

```scheme
(import (srfi s128 comparators) (srfi s125 hash-tables))
```

Both are bucketed under curry's three native equivalence modes (eq?/eqv?/equal?, from `src/set.h`) exactly as [`(srfi s69 hash-tables)`](s69-s90.md) already does: `eq-comparator`/`eqv-comparator` map to the matching native mode; every other comparator (including `string-comparator`, a custom comparator whose equality happens to be `equal?`-compatible, or `default-comparator`) is bucketed under native `equal?` mode. This is exact whenever the comparator's equality predicate agrees with `equal?` — true for every comparator [`(srfi s128 comparators)`](s128.md) ships and for the overwhelming majority of user-defined ones; a comparator with a genuinely finer or coarser custom equality only buckets correctly to the extent it happens to agree with `equal?`'s structural notion.

**A note on multiple return values:** several procedures below (`hash-table-entries`) return two values via `values`. Consume them with `call-with-values`, not `let-values` — `let-values`/`let*-values` are currently unsupported by curry's bytecode compiler (only the tree-walker handles them), so they raise `unbound-variable` in ordinary compiled/`-e` execution.

## `(srfi s125 hash-tables)` — comparator-keyed hash tables

[SRFI-125](https://srfi.schemers.org/srfi-125/).

#### `(make-hash-table comparator)` → *hash-table*
#### `(hash-table comparator key value ...)` → *hash-table*

`make-hash-table` creates an empty table using `comparator`'s equality (as described above) for bucketing. `hash-table` also populates it from the given `key value ...` pairs (later pairs overwrite earlier ones for the same key). Curry's implementation ignores any additional arguments the full SRFI accepts (e.g. an initial capacity hint).

#### `(hash-table? obj)` → *boolean*
#### `(hash-table-comparator t)` → *comparator*

The comparator `t` was created with (or `equal-comparator` for a table created some other way, e.g. curry's raw builtin `make-hash-table` directly).

#### `(hash-table-size t)` → *exact integer*
#### `(hash-table-count t)` → *exact integer* — alias for `hash-table-size`
#### `(hash-table-empty? t)` → *boolean*
#### `(hash-table-contains? t key)` → *boolean*
#### `(hash-table-exists? t key)` → *boolean* — alias for `hash-table-contains?`

#### `(hash-table-ref t key)` → *value*
#### `(hash-table-ref t key failure)` → *value*
#### `(hash-table-ref t key failure success)` → *value*

Look up `key`. On a miss: with no `failure`, raises; with `failure` (a zero-argument thunk), calls and returns it instead. On a hit: with no `success`, returns the stored value; with `success` (a one-argument procedure), calls it with the value and returns *that*.

```scheme
(hash-table-ref t "a" (lambda () 'missing))                    ; => 1, or 'missing on a miss
(hash-table-ref t "a" (lambda () 0) (lambda (v) (* v 100)))    ; => 100 (found: 1, transformed)
```

#### `(hash-table-ref/default t key default)` → *value*

Like `hash-table-ref` with a failure thunk, but `default` is a plain value returned as-is on a miss (no thunk call).

#### `(hash-table-set! t key value)`
#### `(hash-table-delete! t key ...)`

#### `(hash-table-intern! t key failure)` → *value*

If `key` is present, returns its value. Otherwise calls `failure` (a zero-argument thunk), stores the result under `key`, and returns it — the "get or compute-and-cache" idiom in one call.

#### `(hash-table-update! t key updater)` → *unspecified*
#### `(hash-table-update! t key updater failure)` → *unspecified*
#### `(hash-table-update!/default t key updater default)` → *unspecified*

`(hash-table-set! t key (updater (hash-table-ref t key ...)))` — look up (with the same miss behavior as `hash-table-ref`/`hash-table-ref/default`), apply `updater` to the value, store the result back.

```scheme
(hash-table-update!/default counts word (lambda (n) (+ n 1)) 0)  ; increment-or-initialize
```

#### `(hash-table-clear! t)`
#### `(hash-table-copy t)` → *hash-table*
#### `(hash-table-empty-copy t)` → *hash-table*

`hash-table-copy` is a full independent copy (same comparator, same entries); `hash-table-empty-copy` makes a new empty table with the same comparator, no entries.

#### `(hash-table-keys t)` → *list*
#### `(hash-table-values t)` → *list*
#### `(hash-table-entries t)` → *two values: keys list, values list* (see the note on multiple values above)
#### `(hash-table->alist t)` → *alist of `(key . value)`*
#### `(alist->hash-table alist comparator)` → *hash-table*

Order is unspecified across all of these (whatever order the underlying table iterates its buckets in).

#### `(hash-table-walk t proc)`
#### `(hash-table-for-each t proc)` — alias for `hash-table-walk`

Calls `(proc key value)` for each entry, for effect.

#### `(hash-table-map->list proc t)` → *list*

`(proc key value)` for each entry, collected into a list. Note the argument order is *reversed* from `hash-table-walk` (`proc` first here) — this matches the SRFI text exactly, not a typo.

#### `(hash-table-fold t proc init)` → *value*

Left fold: `(proc key value acc)` for each entry, threading the accumulator, starting from `init`.

#### `(hash-table-count-matching t pred)` → *exact integer*

Count of entries where `(pred key value)` is true.

#### `(hash-table-map! proc t)` → *t*

Replaces every value in place with `(proc key value)`; returns `t`.

#### `(hash-table-prune! pred t)` → *t*

Deletes every entry where `(pred key value)` is true, in place; returns `t`.

#### `(hash-table-union! t1 t2)` → *t1*
#### `(hash-table-intersection! t1 t2)` → *t1*
#### `(hash-table-difference! t1 t2)` → *t1*

Mutate `t1` in place to be its union/intersection/difference with `t2` (keyed on presence, `t1`'s existing values win on key overlap for union), and return `t1`. `t2` is never modified.

```scheme
(import (srfi s128 comparators) (srfi s125 hash-tables))
(define t (make-hash-table string-comparator))
(hash-table-set! t "a" 1)
(hash-table-ref t "a" (lambda () 'missing))  ; => 1
```

## `(srfi s126 hashtables)` — R6RS-style naming

[SRFI-126](https://srfi.schemers.org/srfi-126/) layers R6RS `hashtable-*` naming on top of `(srfi s125 hash-tables)` — every procedure below just forwards to (or is a thin wrapper over) the `hash-table-*` procedure of the analogous name above, so it's safe to combine with `(srfi s125 hash-tables)` in the same program (unlike [`(srfi s69 hash-tables)`](s69-s90.md), which shares generic names with s125 and *isn't* safe to combine with it).

#### `(make-eq-hashtable)` → *hashtable*
#### `(make-eqv-hashtable)` → *hashtable*
#### `(make-hashtable hash-fn equiv-fn)` → *hashtable*

`make-hashtable`'s `hash-fn`/`equiv-fn` are honored only to the extent they identify one of curry's three native equivalences: `equiv-fn` `eq?` or `eqv?` selects that mode; anything else (including a genuinely custom predicate) falls back to `equal?` mode, same caveat as `make-hash-table` above. `hash-fn` itself is accepted but not otherwise used (curry's tables don't take a caller-supplied hash function).

#### `hashtable?`, `hashtable-set!`, `hashtable-delete!`, `hashtable-contains?`, `hashtable-copy`, `hashtable-clear!`, `hashtable-size`, `hashtable-keys`, `hashtable-values`, `hashtable-entries`, `hashtable->alist`, `hashtable-walk`

Direct aliases for the matching `hash-table-*` procedure above.

#### `(hashtable-ref t key default)` → *value*

Like `hash-table-ref/default` (a plain default value, not a thunk — note this differs from s125's own `hash-table-ref`, which takes a thunk).

#### `(hashtable-update! t key proc default)` → *unspecified*

Like `hash-table-update!/default`.

#### `(hashtable-mutable? t)` → `#t`

Always `#t` — curry has no immutable hash-table variant.

#### `(hashtable-equivalence-function t)` → *procedure*

`t`'s comparator's equality predicate.

#### `(hashtable-hash-function t)` → *procedure or `#f`*

Per R6RS: `#f` for an `eq?`/`eqv?`-mode table (no user-level hash function reported); `equal-hash` for anything else.

#### `(equal-hash obj)` / `(string-hash s)` / `(symbol-hash s)` → *non-negative exact integer*

Hash functions matching `equal-comparator`/`string-comparator`/`symbol-comparator`'s own hash — equal inputs hash equally, but the specific numbers aren't meant to match any other implementation's.
