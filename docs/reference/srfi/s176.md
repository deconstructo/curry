# `(srfi s176 version-flag)` — SRFI-176

```scheme
(import (srfi s176 version-flag))   ; or (srfi 176), or (srfi srfi-176)
```

[SRFI-176](https://srfi.schemers.org/srfi-176/) Version flag: a standard `(version-alist)` procedure plus a `-V` command-line flag, both exposing implementation-identity/build/feature information in LOSE (Line-Oriented S-Expressions) format — easy to parse from Scheme, C, or a shell script.

## `-V`

Prints every property `(version-alist)` returns, in LOSE (line-oriented S-expression) format, and exits `0`. Each property is one line starting with `(` in column 1, so a LOSE-aware parser reads the output as one alist, and a shell script can use `grep '^(version '`.

```console
$ curry -V
(command "curry")
(website "https://github.com/deconstructo/curry")
(version "1.27.0")
(languages scheme r7rs)
(build.date "2026-10-18T09:30:12Z")
(build.platform "Darwin-arm64")
(build.configure "-DBUILD_FFI=ON" "-DBUILD_LLVM=ON" "-DCMAKE_BUILD_TYPE=Release" "-DCMAKE_INSTALL_PREFIX=/usr/local")
(build.git.branch "main")
(build.git.tag "v1.27.0")
(build.git.commit "d80149d...")
(scheme.id curry)
(scheme.srfi 0 1 4 8 9 14 ... 273 279)
(scheme.features curry r7rs exact-closed ratios full-unicode darwin unix posix lp64)
(scheme.path "/usr/local/lib/curry/modules")
(c.version "AppleClang 21.0.0.21000334")
(c.compile "/usr/bin/cc" "-O2")
(c.link "/usr/bin/cc" "-lgc" "/opt/homebrew/lib/libgmp.dylib" "-lm")
(c.type-bits (char 8) (short 16) (int 32) (long 64) (long-long 64) (float 32) (double 64) (size_t 64) (pointer 64))
```

(The values above are an example; the git commit is shortened here.) `-V` and `(version-alist)` are built from the same C function (`curry_version_alist()` in `src/version_info.c`), so they always report the same properties in the same order. Because `scheme.features` and `scheme.path` need the runtime, `-V` starts the runtime first, as running a script does; it is not as fast as `-v`.

LOSE strings have two escapes, `\"` and `\\`, and no newlines. A control character in a value (for example in a changed file name) is printed as a space.

## `(version-alist)` → *association list*

Returns the same data to a running program as an association list: each element is `(property value ...)`. Callers must not modify it.

```scheme
(import (srfi 176))
(cdr (assq 'version (version-alist)))      ; => ("1.27.0")
(cdr (assq 'c.type-bits (version-alist)))  ; => ((char 8) (short 16) ... (pointer 64))
```

### Properties

A property whose value cannot be determined is left out; every property is optional in the SRFI.

| Property | Value |
|---|---|
| `command` | `"curry"` |
| `website` | the project URL |
| `version` | `CURRY_VERSION` (`src/version.h`) |
| `languages` | `scheme r7rs` |
| `build.date` | UTC build time, RFC 3339 (`2026-10-18T09:30:12Z`). Set when the build information is first generated; kept until the git state changes. Honours `SOURCE_DATE_EPOCH` for reproducible builds. |
| `build.platform` | CMake system and processor, for example `Darwin-arm64` |
| `build.configure` | the CMake options that decide what the binary contains: every `BUILD_*` option and `CMAKE_BUILD_TYPE`, as `-DNAME=VALUE` strings (plus `CMAKE_INSTALL_PREFIX` and `CMAKE_PREFIX_PATH` with `-DCURRY_BUILD_INFO_PATHS=ON`) |
| `build.git.commit` | full commit hash |
| `build.git.branch` | branch name; absent on a detached `HEAD` |
| `build.git.tag` | tag, only when `HEAD` is exactly at a tag |
| `build.git.modified` | changed or untracked files at build time (at most 100); absent when the tree was clean. Only with `-DCURRY_BUILD_INFO_PATHS=ON`. |
| `scheme.id` | `curry` |
| `scheme.srfi` | the SRFI numbers curry provides, ascending |
| `scheme.features` | the same list `(features)` returns |
| `scheme.path` | the module search directories, in search order. Only with `-DCURRY_BUILD_INFO_PATHS=ON`. |
| `c.version` | C compiler name and version, for example `AppleClang 21.0.0.21000334` |
| `c.compile` | the C compiler (file name only by default) and the flags from `CMAKE_C_FLAGS` and the build type's flags. Approximate: it does not include `-std`, `-I`, `-D` or per-target options. |
| `c.link` | the C compiler as linker, the linker flags and the libraries `libgc`, `libgmp`, `libm`. Approximate, like `c.compile`. |
| `c.type-bits` | `(name bits)` pairs for `char short int long long-long float double size_t pointer`, measured by the C compiler that built curry |

The `build.git.*` properties are present only when curry is built from a git checkout (the source directory must be the top of the work tree). A build from a release tarball, as Homebrew does, has `build.date` but no `build.git.*` properties.

### Build-machine paths are left out by default

A binary carries its `-V` output with it, and any script that can call `(version-alist)` (no import is needed for `(curry-version-alist)`), including a sandboxed or remote script such as an MCP tool, can read it. Paths and file names from the build machine can reveal user names and directory layout, so by default they are not recorded. With the default configuration:

- `scheme.path` and `build.git.modified` are absent.
- `c.compile` and `c.link` keep the compiler's file name (`cc`), flags that name no path, and libraries by name (`-lgmp`). Flags with a `/` and `-I`, `-L`, `-isysroot` and similar flags are dropped.
- `build.configure` lists the `BUILD_*` options and `CMAKE_BUILD_TYPE`, but not `CMAKE_INSTALL_PREFIX` or `CMAKE_PREFIX_PATH`.

Configure with `-DCURRY_BUILD_INFO_PATHS=ON` to record all of them, for example for a local debugging build. `tests/test_cli.sh` checks that a default build prints no absolute path.

### Keeping `scheme.srfi` correct

`scheme.srfi` is a literal list (`SRFI_NUMBERS` in `src/version_info.c`), not a scan of the module directory, so the result does not depend on where the modules are installed. `tests/test_cli.sh` compares it with the files in `lib/curry/modules/srfi/` (plus the built-in SRFI 0 and 61). When you add a SRFI, add its number to the list or that test fails. Before this change the list had drifted and was missing 28, 29, 189, 208, 224 and 272.

## `(curry-version)` → *string*

Also: `(curry-version-alist)` is the builtin that `version-alist` calls. `(curry-version)` is a small addition alongside this SRFI: a Scheme-visible accessor for curry's own version string (`CURRY_VERSION`, `src/version.h`) — the single source of truth `-v`/`-V`/`version-alist`'s own `version` property and the release tooling all already share, rather than a second hand-maintained copy.
