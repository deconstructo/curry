# `(srfi s225 dictionaries)` — SRFI-225

```scheme
(import (srfi s225 dictionaries))   ; or (srfi 225), or (srfi srfi-225)
```

[SRFI-225](https://srfi.schemers.org/srfi-225/) Dictionaries: a uniform interface over key/value mapping types that don't otherwise share an API — alists, curry's own hash tables, or a user-defined type. Every generic `dict-*` procedure below takes a **Dictionary Type Object (DTO)** explicitly as its first argument and dispatches through it; there is no global type registry or automatic predicate-based dispatch (mirroring the SRFI's own design — every one of its procedure signatures leads with a DTO).

```scheme
(define d (dict-set! equal-alist-dto '() 'a 1 'b 2))
(dict-ref equal-alist-dto d 'a)              ; => 1
(dict-fold equal-alist-dto (lambda (k v acc) (+ v acc)) 0 d)  ; => 3
```

## Pure vs. impure dictionaries

A **pure** dictionary type (alists here) returns a *new* instance from every update; the dict argument passed in is never itself mutated. An **impure** type (curry's hash tables) mutates in place and returns the same object. `(dict-pure? dto dict)` tells you which. Every `!`-suffixed update procedure works uniformly across both — for a pure type, rebind the dict argument to what it returns; for an impure type, the return value is the same object you passed in, so rebinding is harmless but not required.

## Required vs. derived operations

Only 7 primitives are required per DTO: `dictionary?`, `dict-comparator`, `dict-find-update!`, `dict-map`, `dict-pure?`, `dict-remove`, `dict-size`. Every other generic procedure (`dict-ref`, `dict-set!`, `dict-fold`, `dict-for-each`, ...) is *derived* from those 7 automatically — `dto-ref` computes and caches a working default the first time an unset optional proc-id is asked for. `make-dto` only ever raises for a *missing required* proc-id; every optional one always has a fallback, though a DTO can still supply its own more direct/efficient implementation for any optional proc-id it wants (see `srfi-69-dto`'s own `dict-for-each`, e.g., which walks the real hash table directly instead of going through the derived-from-`dict-map` default).

`dict-find-update!` is the one genuine workhorse: every read (`dict-ref`, `dict-contains?`) and pure write (`dict-set!`, `dict-adjoin!`, `dict-replace!`, `dict-delete!`, `dict-intern!`) is expressible as a single `dict-find-update!` call whose failure/success callbacks choose which of *its own* four inner continuations (`insert`/`ignore` on absence, `update`/`delete` on presence) to invoke.

## Predicates

#### `(dictionary? dto obj)` → *boolean*
#### `(dict-empty? dto dict)` → *boolean*
#### `(dict-contains? dto dict key)` → *boolean*
#### `(dict=? dto val=? dict1 dict2)` → *boolean*

`#t` if `dict1`/`dict2` have identical keys with values matching under `val=?`.

#### `(dict-pure? dto dict)` → *boolean*

## Accessors

#### `(dict-ref dto dict key [failure [success]])`

If `key` is present, calls `(success value)` (default: identity) and returns the result. If absent, calls `(failure)` (default: raises a `dictionary-error`) and returns *that* result.

#### `(dict-ref/default dto dict key default)`

#### `(dict-comparator dto dict)` → *[SRFI-128](s128.md) comparator, or `#f`*

A comparator over `dict`'s own keys (type test, equality, ordering if any, hash if any) — not over the dict itself.

## Update procedures

#### `(dict-set! dto dict obj ...)`

`obj ...` alternates key/value; later pairs override earlier ones for a repeated key. Returns the updated dict (new instance if pure, same mutated instance if impure — see above).

#### `(dict-adjoin! dto dict obj ...)`

Like `dict-set!`, but an already-present key keeps its *original* value.

#### `(dict-delete! dto dict key ...)`
#### `(dict-delete-all! dto dict keylist)`

#### `(dict-replace! dto dict key value)`

No-op (returns `dict` unchanged) if `key` isn't present.

#### `(dict-intern! dto dict key failure)` → *(values new-dict value)*

If `key` is present, returns `(values dict value)`. If absent, calls `(failure)` to compute a value, adds it, and returns `(values new-dict value)`.

#### `(dict-update! dto dict key updater [failure [success]])`

Fetches `key`'s value via `dict-ref` (same `failure`/`success` defaults), applies `updater`, and `dict-set!`s the result.

#### `(dict-update/default! dto dict key updater default)`

Same, using `dict-ref/default` with `default`.

#### `(dict-pop! dto dict)` → *(values new-dict key value)*

Removes and returns one association — the first, for a dict type whose iteration order is well-defined; otherwise arbitrary. Raises a `dictionary-error` on an empty dict.

#### `(dict-find-update! dto dict key failure success)`

The low-level primitive every operation above reduces to. `failure` is called as `(failure insert ignore)` when `key` is absent — call `(insert v)` to add `key`→`v` and return the new dict, or `(ignore)` to return `dict` unchanged. `success` is called as `(success matched-key value update delete)` when present — call `(update new-key new-value)` (with `new-key` equal to `matched-key`) to replace the association, or `(delete)` to remove it. Whatever `failure`/`success` return becomes `dict-find-update!`'s own return value — used directly as a read op (never invoking `insert`/`ignore`/`update`/`delete` at all) works just as well as a write op.

## Mapping and filtering

#### `(dict-map dto proc dict)` → *new dict*

Applies `(proc key value)` to produce each new value; always returns a fresh dict (never mutates `dict` in place, even for an impure type).

#### `(dict-filter dto pred dict)` / `(dict-remove dto pred dict)`

Keep (`dict-filter`) or drop (`dict-remove`) associations where `(pred key value)` is true. `dict-remove` is one of the 7 required primitives; `dict-filter` is its complement.

## Whole-dictionary operations

`(dict-size dto dict)`, `(dict-count dto pred dict)`, `(dict-any dto pred dict)` (short-circuits on first truthy `(pred key value)`), `(dict-every dto pred dict)` (short-circuits on first falsy), `(dict-keys dto dict)`, `(dict-values dto dict)`, `(dict-entries dto dict)` → `(values keys values)`, `(dict-fold dto proc knil dict)` (`(proc key value acc)`), `(dict-map->list dto proc dict)`, `(dict->alist dto dict)`.

## Iteration

#### `(dict-for-each dto proc dict [start [end]])`

`start`/`end` restrict by key range — only meaningful (and only honored) for a DTO whose `dict-comparator` reports an ordering; every DTO shipped with curry is unordered, so `start`/`end` are accepted but have no effect here.

#### `(dict->generator dto dict [start [end]])` → *[SRFI-158](s158.md) generator*

Yields each association as a `(key . value)` pair. Materializes eagerly into a snapshot at call time (not a lazy live view) — this codebase's implementation choice, stricter than but consistent with the SRFI's own "don't mutate `dict` until the generator is exhausted" caveat.

#### `(dict-set!-accumulator dto dict)` / `(dict-adjoin!-accumulator dto dict)` → *[SRFI-158](s158.md) accumulator*

Each call with a `(key . value)` pair does one `dict-set!`/`dict-adjoin!`; a call with the eof-object returns the accumulated dict.

## DTO construction and introspection

#### `(dto? obj)` → *boolean*

#### `(make-dto proc-id proc ...)` → *dto*

Alternating proc-id/procedure pairs. Raises a `dictionary-error` if any of the 7 required proc-ids (`dictionary?-id`, `dict-comparator-id`, `dict-find-update!-id`, `dict-map-id`, `dict-pure?-id`, `dict-remove-id`, `dict-size-id`) is missing. Every proc-id this library exports (required and optional) is a plain interned symbol, usable directly as a hash-table key or in `eq?` comparisons.

#### `(dto-ref dto proc-id)` → *procedure*

The procedure implementing `proc-id` — the DTO's own, if it supplied one, or a derived default (computed once, then cached on the DTO for subsequent calls).

#### `(make-alist-dto equal?)` → *dto*

Builds a pure DTO over plain association lists, using `equal?` as the key-equality predicate. New keys are added to the *front* of the list (so `dict-keys`/`dict->alist`/etc. return most-recently-added-first, matching the SRFI's own alist convention).

## Shipped DTOs

| DTO | Backing type | Pure? |
|---|---|---|
| `eqv-alist-dto` | plain alist, `eqv?` keys | yes |
| `equal-alist-dto` | plain alist, `equal?` keys | yes |
| `srfi-69-dto` | [`(srfi 69)`](s69.md) hash tables | no |
| `hash-table-dto`, `srfi-126-dto` | [`(srfi 126)`](s125-s126.md) hashtables | no |

`hash-table-dto` and `srfi-126-dto` are `eq?`-identical — curry's own "R6RS-flavored naming" hash-table layer (`(srfi s126 hashtables)`) is the closest thing curry has to genuine `(rnrs hashtables)`, so both of the SRFI's own spec-named DTOs point at the same wrapper. The SRFI's own conditionally-exported `mapping-dto`/`hash-mapping-dto` ([SRFI-146](https://srfi.schemers.org/srfi-146/) persistent mappings) and a [SRFI-167](https://srfi.schemers.org/srfi-167/)-backed DTO are not shipped, since neither SRFI is implemented in curry — exactly the "conditionally exported… if available" case the SRFI's own text anticipates.
