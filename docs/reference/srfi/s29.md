# `(srfi s29 localization)` — SRFI-29

```scheme
(import (srfi s29 localization))   ; or (srfi 29), or (srfi srfi-29)
```

[SRFI-29](https://srfi.schemers.org/srfi-29/) Localization: register locale-specific translations of message templates (ordinary [SRFI-28](s28.md) format strings) under a **bundle specifier**, then retrieve the right one later for whatever the *current* locale happens to be.

```scheme
(import (srfi 28) (srfi 29))

(declare-bundle! '(mathlib) '((add-error . "Cannot add ~a and ~a.")))
(declare-bundle! '(mathlib fr) '((add-error . "Impossible d'ajouter ~a et ~a.")))

(format (localized-template 'mathlib 'add-error) 3 "x")
; => "Cannot add 3 and x."   (current-language defaults to 'en)

(current-language 'fr)
(format (localized-template 'mathlib 'add-error) 3 "x")
; => "Impossible d'ajouter 3 et x."
```

## Bundle specifiers

A list of symbols, most-to-least specific: `(package-name language country details...)`. Only `package-name` is required — `(mathlib)`, `(mathlib fr)`, and `(mathlib fr ca)` are all valid, increasingly specific specifiers for the same package.

## Locale state

#### `(current-language)` → *symbol* — default `'en`
#### `(current-language symbol)`
#### `(current-country)` → *symbol* — default `'us`
#### `(current-country symbol)`
#### `(current-locale-details)` → *list of symbols* — default `'()`
#### `(current-locale-details list)`

Each is a plain global mutable value, per the SRFI's own reference implementation — not a full `parameterize`-integrated dynamic parameter (the SRFI's own text only ever requires "for the executing thread, or the entire system if no thread distinction is made," leaving genuine per-thread isolation optional). In practice, curry's own actors don't share a mutable global frame with each other's top-level `define`s, so each actor already gets an independent binding of these three variables — inherited from how curry's library/environment model already works, not something specially engineered for this SRFI.

## Bundle management

#### `(declare-bundle! bundle-specifier alist)`

`alist` maps template-name symbols to format-string templates. Re-declaring the same specifier **replaces** the whole bundle (not merged with the old one). Raises if `bundle-specifier` isn't a non-empty list of symbols.

#### `(store-bundle! bundle-specifier)` → `#f`
#### `(load-bundle! bundle-specifier)` → `#f`

Always `#f` — persistence to/from external storage, which this SRFI's own text explicitly permits a compliant implementation to skip entirely ("compliant systems may always return `#f`"). `load-bundle!` returning `#f` leaves the bundle registry unchanged, per spec.

## Message retrieval

#### `(localized-template package-name message-template-name)` → *string or `#f`*

Searches bundle specifiers from most to least specific — `(package lang country . details)`, then with the last element dropped, and so on down to just `(package)` — returning the template string from the *first* bundle along that path that actually has an entry for `message-template-name`. A bundle registered at a more specific level that simply doesn't override a given message is skipped over, not treated as a dead end: e.g. an `fr-ca` bundle that only overrides `greeting` still falls through to the base bundle for any *other* message name. Returns `#f` if nothing is found all the way down to the bare package name.

The returned string is an ordinary [SRFI-28](s28.md) format string, including its `~N@*` positional-reference extension — pass it straight to `format` along with the message's own arguments.
