# `(srfi s209 enums)` — SRFI-209

```scheme
(import (srfi s209 enums))
```

[SRFI-209](https://srfi.schemers.org/srfi-209/): enums and enum sets — type-safe, ordered symbolic constants (each with a name, a 0-based ordinal, and an optional value), grouped into disjoint *enum types*, plus immutable-by-default *enum sets* (subsets of a single type's enums) with the usual set algebra.

## Enum types and enums

#### `(make-enum-type list)` → *enum-type*

Each element of `list` is either a symbol (an enum name; its value defaults to its position/ordinal in `list`) or a two-element list `(name value)` (explicit value). Names must be distinct within the type.

```scheme
(define color (make-enum-type '(red orange yellow green cyan blue violet)))
(define pizza (make-enum-type '((margherita "tomato and mozzarella") (funghi "mushrooms"))))
```

#### `(enum-type? obj)` → *boolean*
#### `(enum? obj)` → *boolean*
#### `(enum-type-contains? enum-type enum)` → *boolean*

#### `(enum-type enum)` → *enum-type*
#### `(enum-name enum)` → *symbol*
#### `(enum-ordinal enum)` → *exact integer*
#### `(enum-value enum)` → *object*

```scheme
(define color-red (enum-name->enum color 'red))
(enum-name color-red)     ; => red
(enum-ordinal color-red)  ; => 0
```

#### `(enum=? enum ...)`, `(enum<? enum ...)`, `(enum>? enum ...)`, `(enum<=? enum ...)`, `(enum>=? enum ...)` → *boolean*

Compare by ordinal (`enum=?` is equivalent, since a type never has two distinct enum objects sharing an ordinal). Raises if any two arguments belong to different enum types.

### Finders

#### `(enum-name->enum enum-type symbol)` → *enum or `#f`*
#### `(enum-ordinal->enum enum-type exact-integer)` → *enum or `#f`*

#### `(enum-name->ordinal enum-type symbol)` → *exact integer*
#### `(enum-name->value enum-type symbol)` → *object*
#### `(enum-ordinal->name enum-type exact-integer)` → *symbol*
#### `(enum-ordinal->value enum-type exact-integer)` → *object*

The `->enum` finders return `#f` on a miss; the other four **raise** instead — there's no finder by value, since values need not be unique.

### Enum-type queries

#### `(enum-type-size enum-type)` → *exact integer*
#### `(enum-min enum-type)`, `(enum-max enum-type)` → *enum*
#### `(enum-type-enums enum-type)` → *list of enums, ascending ordinal*
#### `(enum-type-names enum-type)` → *list of symbols, ascending ordinal*
#### `(enum-type-values enum-type)` → *list of values, ascending ordinal*

### Navigation

#### `(enum-next enum)` → *enum or `#f`*
#### `(enum-prev enum)` → *enum or `#f`*

The adjacent enum by ordinal within the same type, or `#f` past either boundary.

### Comparator

#### `(make-enum-comparator enum-type)` → *[SRFI-128](s128.md) comparator*

Orders enums of `enum-type` by ordinal; hashable.

```scheme
(define color-cmp (make-enum-comparator color))
(<? color-cmp color-red (enum-name->enum color 'blue))  ; => #t
```

## Enum sets

An enum set is an immutable-by-default subset of one enum type's enums. Every whole-set traversal (`enum-set->enum-list`, `-map->list`, `-for-each`, `-fold`, `-filter`, `-remove`) visits members in ascending ordinal order.

### Construction

#### `(enum-empty-set enum-type)` → *enum-set, no members*
#### `(enum-type->enum-set enum-type)` → *enum-set, every member of the type*
#### `(enum-set enum-type enum ...)` → *enum-set*
#### `(list->enum-set enum-type list)` → *enum-set*
#### `(enum-set-copy enum-set)` → *enum-set, independent copy*

`enum-set` and `list->enum-set` raise if any given enum belongs to a different type than `enum-type`.

#### `(enum-set-projection enum-type-or-set enum-set)` → *enum-set*

Maps `enum-set`'s members into `enum-type-or-set`'s type **by name** — useful for two related-but-distinct enum types that share some names. Raises if any of `enum-set`'s member names isn't present in the target type.

```scheme
(define us-traffic-light (make-enum-type '(red yellow green)))
(enum-set-map->list enum-name
  (enum-set-projection us-traffic-light (enum-set color color-red (enum-name->enum color 'green))))
; => (red green)
```

### R6RS compatibility (deprecated — prefer the SRFI-209-native forms above)

#### `(make-enumeration symbol-list)` → *enum-set, containing a freshly made enum type where every value equals its name*
#### `(enum-set-universe enum-set)` → *enum-set, every member of `enum-set`'s type*
#### `(enum-set-constructor enum-set)` → *procedure: `(list-of-symbols) → enum-set`*
#### `(enum-set-member? symbol enum-set)` → *boolean* — raises if `symbol` isn't a name in the type
#### `(enum-set->list enum-set)` → *list of symbols (names, not enums)*
#### `(enum-set-indexer enum-set)` → *procedure: `(symbol) → ordinal or #f`*

### Predicates

#### `(enum-set? obj)` → *boolean*
#### `(enum-set-contains? enum-set enum)` → *boolean* — raises if `enum`'s type doesn't match
#### `(enum-set-empty? enum-set)` → *boolean*
#### `(enum-set-disjoint? enum-set enum-set)` → *boolean* — raises if types differ
#### `(enum-set=? s1 s2)`, `(enum-set<? s1 s2)`, `(enum-set>? s1 s2)`, `(enum-set<=? s1 s2)`, `(enum-set>=? s1 s2)` → *boolean* — set equality / proper and improper subset-or-superset; raise if `s1` and `s2` have different types
#### `(enum-set-subset? s1 s2)` → *boolean*

Unlike the comparison operators above, this one **compares by name and works across different enum types** — every name in `s1` must also appear (by name) somewhere in `s2`.

```scheme
(enum-set-subset? (enum-set us-traffic-light (enum-name->enum us-traffic-light 'red))
                   (enum-set color color-red))
; => #t
```

#### `(enum-set-any? pred enum-set)` → *boolean*
#### `(enum-set-every? pred enum-set)` → *boolean*

### Accessor

#### `(enum-set-type enum-set)` → *enum-type*

### Mutation

Each pair does the same thing; the `!` form mutates `enum-set` in place and returns it (any other reference to the same object now sees the change), the plain form copies first and leaves the original untouched.

#### `(enum-set-adjoin enum-set enum ...)` / `(enum-set-adjoin! enum-set enum ...)`
#### `(enum-set-delete enum-set enum ...)` / `(enum-set-delete! enum-set enum ...)`
#### `(enum-set-delete-all enum-set list)` / `(enum-set-delete-all! enum-set list)`

`enum-set-delete-all` takes the enums to remove pre-collected as one list, rather than as individual arguments like `enum-set-delete`.

### Whole-set operations

#### `(enum-set-size enum-set)` → *exact integer*
#### `(enum-set->enum-list enum-set)` → *list of enums, ascending ordinal*
#### `(enum-set-count pred enum-set)` → *exact integer*
#### `(enum-set-filter pred enum-set)` → *enum-set, members satisfying `pred`*
#### `(enum-set-remove pred enum-set)` → *enum-set, members NOT satisfying `pred`*
#### `(enum-set-map->list proc enum-set)` → *list*
#### `(enum-set-for-each proc enum-set)`
#### `(enum-set-fold proc nil enum-set)` → *object*

`(proc member acc)`, threading the accumulator from `nil`, ascending ordinal order — so `(enum-set-fold cons '() s)` builds the reverse of `(enum-set->enum-list s)`.

```scheme
(enum-set-count (lambda (e) (> (enum-ordinal e) 3)) (enum-type->enum-set color))  ; => 3
```

### Logical operations

Same functional/`!` pairing as the mutation operators above.

#### `(enum-set-complement enum-set)` / `(enum-set-complement! enum-set)` → *every enum of the type NOT in `enum-set`*
#### `(enum-set-union s1 s2)` / `(enum-set-union! s1 s2)`
#### `(enum-set-intersection s1 s2)` / `(enum-set-intersection! s1 s2)`
#### `(enum-set-difference s1 s2)` / `(enum-set-difference! s1 s2)`
#### `(enum-set-xor s1 s2)` / `(enum-set-xor! s1 s2)`

`union`/`intersection`/`difference`/`xor` all raise if `s1` and `s2` have different types.

## `define-enum` / `define-enumeration`

```scheme
(define-enum type-name (name-value ...) constructor-name)
(define-enumeration type-name (name-value ...) constructor-name)
```

Both allocate a new enum type (same `name-value` grammar as `make-enum-type` — a bare symbol or a `(symbol value)` pair) and bind two macros:

- `type-name`, used as `(type-name symbol)`: for `define-enum`, returns the named **enum**; for `define-enumeration`, returns the **symbol itself** (still validated — raises if `symbol` doesn't name an enum of the type). `define-enumeration`'s enums also default their value to their own name rather than their ordinal, matching R6RS's `make-enumeration`.
- `constructor-name`, used as `(constructor-name symbol ...)` (zero or more bare names, possibly repeated): expands to an expression building an **enum set** of those enums. Behaves identically for both macros — always enums, never bare symbols, even under `define-enumeration`. Raises if any name isn't in the type.

```scheme
(define-enum color (red orange yellow green cyan blue violet) color-set)
(enum-name (color red))              ; => red
(enum-set-map->list enum-name (color-set red blue))  ; => (red blue)

(define-enumeration suit (clubs diamonds hearts spades) suit-set)
(suit hearts)                        ; => hearts   (the symbol, not an enum)
(enum-set-map->list enum-name (suit-set hearts spades))  ; => (hearts spades)
```

`type-name` is bound **only** as a macro — there's no separate variable holding the raw enum-type object (get it from any of the type's own enums via `(enum-type (color red))` if needed). Multiple `define-enum`/`define-enumeration` forms in the same scope are fully independent of each other, each with its own type.

**Limitation**: `type-name`/`constructor-name` resolve to their underlying enum type through a private registry keyed on the pair of names, not through a truly hygienic mechanism (curry's `syntax-rules` has no `gensym`/`datum->syntax` to synthesize a fresh identifier per expansion). Two libraries authored independently that both happen to choose the *same* `type-name` **and** the *same* `constructor-name` for unrelated `define-enum`/`define-enumeration` types will collide if both are imported into one program — including under an R7RS renaming import, which doesn't help here since the registry lookup uses the original name, not the renamed one. Give each type a name pair unlikely to collide with another library's if you're combining `define-enum` types from code you don't control.
