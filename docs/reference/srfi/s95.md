# `(srfi s95 sorting)` — SRFI-95 Sorting and Merging

```scheme
(import (srfi s95 sorting))
```

[SRFI-95](https://srfi.schemers.org/srfi-95/): `sort`/`sort!`/`merge`/`merge!`/`sorted?` over lists and vectors, with `(sequence less? [key])` argument order and an optional per-element `key` extractor.

Predates and overlaps with [SRFI-132](s132-s133.md) (`(srfi s132 sorting)`), already implemented in curry: same merge-sort algorithm underneath, but 132's argument order is `(less? sequence)` with no `key` parameter, while 95's is `(sequence less? [key])`. Rather than a second sort implementation, this library is a thin argument-reordering/key-wrapping shim over SRFI-132's real logic — every procedure here is stable, same as SRFI-132's own.

#### `(sorted? sequence less? [key])` — *procedure*

`#t` if `sequence` (a list or vector) is already in non-decreasing order per `less?`.

#### `(sort sequence less? [key])` → new sequence — *procedure*

Non-destructive. Returns a sequence of the same type (list or vector) as `sequence`.

```scheme
(sort (list 3 1 2) <)                          ; => (1 2 3)
(sort (list "bb" "a" "ccc") < string-length)    ; => ("a" "bb" "ccc")
```

#### `(sort! sequence less? [key])` — *procedure*

May reuse/mutate `sequence`'s storage. For a vector, mutates and returns it in place. For a list, curry's underlying SRFI-132 sort is non-destructive (permitted by both SRFI-132 and SRFI-95 — neither mandates that `sort!` actually reuse pairs), so treat the return value as the result either way rather than assuming the input list itself changed.

#### `(merge list1 list2 less? [key])` → new list — *procedure*

Merges two already-sorted lists into a freshly allocated sorted list.

#### `(merge! list1 list2 less? [key])` — *procedure*

Same as `merge`, permitted to reuse pairs; curry's implementation delegates to the same (non-destructive) merge either way.
