# `(srfi s111 boxes)` — SRFI-111

```scheme
(import (srfi s111 boxes))
```

[SRFI-111](https://srfi.schemers.org/srfi-111/): a *box* is a single-slot mutable container — the minimal building block for shared mutable state, useful anywhere you need a mutable cell that isn't itself a variable binding (closures over shared state, "out parameters", `set!`-free mutation from multiple closures).

#### `(box v)` → *box*

Creates a new box holding `v`.

#### `(box? obj)` → *boolean*

`#t` iff `obj` is a box.

#### `(unbox b)` → *value*

Returns the value currently in `b`.

#### `(set-box! b v)`

Replaces the value in `b` with `v`.

```scheme
(define b (box 5))
(box? b)          ; => #t
(unbox b)          ; => 5
(set-box! b 10)
(unbox b)          ; => 10
```

Each call to `box` creates a fresh, independent box — two boxes holding the same value are `equal?` but not `eq?`:

```scheme
(eq? (box 1) (box 1))  ; => #f
```

## Relationship to SRFI-195

curry's `box`/`box?`/`unbox`/`set-box!` are actually implemented as the zero-or-more-values form that [SRFI-195](s195.md) requires — a plain `(box v)`/`(unbox b)` behaves exactly per this SRFI's single-value contract, since R7RS defines `(values x)` to behave identically to plain `x` in a single-value context. This means [`(srfi s195 multiple-value-boxes)`](s195.md) can be imported alongside this library with no binding conflicts: both libraries share the literal same `box`/`box?`/`unbox`/`set-box!` procedures.

`set-box!` still enforces this SRFI's exactly-one-value contract: calling it with a different number of values than the box currently holds raises an error rather than silently changing the box's arity.

```scheme
(guard (e (#t 'wrong-arity))
  (set-box! (box 1) 2 3))
; => wrong-arity
```
