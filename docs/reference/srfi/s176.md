# `(srfi s176 version-flag)` — SRFI-176

```scheme
(import (srfi s176 version-flag))   ; or (srfi 176), or (srfi srfi-176)
```

[SRFI-176](https://srfi.schemers.org/srfi-176/) Version flag: a standard `(version-alist)` procedure plus a `-V` command-line flag, both exposing implementation-identity/build/feature information in LOSE (Line-Oriented S-Expressions) format — easy to parse from Scheme, C, or a shell script.

## `-V`

```console
$ curry -V
(command "curry")
(website "https://github.com/deconstructo/curry")
(version "1.25.2")
(languages scheme r7rs)
(scheme.id curry)
```

Implemented directly in `src/main.c`, independent of booting the Scheme runtime — matching how curry's pre-existing `-v`/`-h` flags already short-circuit before any VM/module initialization. Exits `0` on success (per the SRFI's own requirement); each property is one top-level S-expression on its own line, its own opening parenthesis in column 1, exactly as LOSE requires — a LOSE-aware parser reads them back into a single alist.

## `(version-alist)` → *association list*

The richer, from-within-a-running-program counterpart to `-V`. Returns everything `-V` prints, plus two properties that genuinely need the module system and core builtins already initialized:

```scheme
(version-alist)
; => ((command "curry")
;     (website "https://github.com/deconstructo/curry")
;     (version "1.25.2")
;     (languages scheme r7rs)
;     (scheme.id curry)
;     (scheme.srfi 0 1 4 8 9 14 18 19 26 27 31 ...)
;     (scheme.features curry r7rs exact-closed ratios full-unicode darwin unix posix lp64))
```

- **`scheme.features`** is exactly curry's own `(features)` builtin's return value — the same list `cond-expand` tests membership against.
- **`scheme.srfi`** enumerates every SRFI curry ships, sorted ascending, including SRFI-0 and SRFI-61 (hardcoded compiler/evaluator special forms with no `.sld` shim of their own to enumerate automatically — see [`s0.md`](s0.md)/[`s61.md`](s61.md)). It's a hand-maintained literal, not computed by scanning `lib/curry/modules/srfi/` at import time — deliberately, so this library stays dependency-free of any optional C module (`(curry posix)`'s `directory-files` is default-on but not guaranteed present) and immune to install-layout assumptions about where the running binary's own module directory lives. Regenerate it (see the library's own header comment for the exact one-liner) whenever SRFI support changes.

Per the SRFI's own text, every property is optional; callers must not modify the returned list.

## `(curry-version)` → *string*

A small addition alongside this SRFI: a Scheme-visible accessor for curry's own version string (`CURRY_VERSION`, `src/version.h`) — the single source of truth `-v`/`-V`/`version-alist`'s own `version` property and the release tooling all already share, rather than a second hand-maintained copy.
