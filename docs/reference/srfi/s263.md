# `(srfi s263 prototype-objects)` — SRFI-263 Prototype Object System

```scheme
(import (srfi s263 prototype-objects))
```

[SRFI-263](https://srfi.schemers.org/srfi-263/): a "Self"-inspired prototype/message-passing object system. Objects are plain procedures invoked as `(obj 'message arg ...)`; new objects are *derived* from existing ones (cloning-with-a-parent-pointer) rather than instantiated from classes. This is a genuinely different paradigm from [`(curry oop)`](../../thoughts/oop.md) (a CLOS-style class/generic-function system already in this codebase, immutable-by-default slots, multiple dispatch) — the two coexist deliberately, not as competing implementations of the same thing.

## Objects, slots, messages

An object holds *slots*, each named by a getter message (and optionally a setter message):

- **value slot** — stores a value, returned by the getter message; the setter message (if any) replaces it.
- **method slot** — stores a procedure; the getter message invokes it with `self` (the original receiver) and `resend` (see below) prepended to the message's own arguments.
- **parent slot** — stores another object; when a message isn't found locally, every parent slot is searched (recursively). Found in exactly one parent's ancestry → used. Found via more than one *distinct* parent → `ambiguous-message-send`. Found nowhere → `message-not-understood`. (Both are themselves ordinary method slots, defined on `*the-root-object*` to signal an error — override them on your own object to change that behavior.)

```scheme
(define pointobj (*the-root-object* 'derive))
(pointobj 'set-value-slot! 'x 'set-x! 10)
(pointobj 'x)           ; => 10
(pointobj 'set-x! 50)
(pointobj 'x)           ; => 50

(pointobj 'set-method-slot! 'double
  (lambda (self resend) (* 2 (self 'x))))
(pointobj 'double)      ; => 100
```

## `resend`

Inside a method body, `resend` is `(resend target-override . args)`:

- `target-override` = `#f` — continue the search at the object's own parents (skips re-checking the level that owns the currently-running method, which would just find the same slot again).
- `target-override` = a specific object — start a fresh search there instead (including that object's own local slots), the way to explicitly disambiguate a multi-parent object.
- `args`, if given, replace the message's original arguments; omitted, the original arguments are reused.

```scheme
(define-object left (*the-root-object*) ((shared self resend) 'left-shared))
(define-object right (*the-root-object*) ((shared self resend) 'right-shared))
(define-object diamond (left right))
(diamond 'shared)  ; => ambiguous-message-send (found via both left and right)

;; disambiguate explicitly
(define-method (diamond shared self resend) (resend right))
(diamond 'shared)  ; => 'right-shared
```

## `derive` / `copy` / `mirror`

- `(obj 'derive)` — a new object whose `parent` slot points at `obj`. The usual way to create objects: `(define o (*the-root-object* 'derive))`.
- `(obj 'copy)` — a new, independent object with `obj`'s own slots cloned in (mutating the copy's value slots doesn't affect `obj`).
- `(obj 'mirror)` — a reflection object with `has-ancestor`, `immediate-ancestor-list`, `full-ancestor-list`, `immediate-slot-list`, `full-slot-list` messages.

## Slot introspection

`slot?`, `slot-getter`, `slot-setter` (`#f` if none), `slot-type` (`'value`, `'method`, or `'parent`) operate on the slot entities `immediate-slot-list`/`full-slot-list` return.

## Syntactic sugar

```scheme
(define-method (obj message self resend . args) body ...)
;; sugar for (obj 'set-method-slot! 'message (lambda (self resend . args) body ...))

(define-object name (parent other-parents ...) slots ...)
(derive-object (parent other-parents ...) slots ...)   ; same, but an expression (no `define`)
(copy-object (parent other-parents ...) slots ...)     ; like derive-object, but 'copy instead of 'derive

;; each slot spec is either:
;;   (getter [setter] value)          -- a value slot
;;   ((message self resend . args) body ...)  -- a method slot
```

```scheme
(define-object o (*the-root-object*)
  (constant set-constant! 5)
  ((add self resend summand) (+ summand (self 'constant))))
(o 'add 10)  ; => 15
```

`other-parents` (multiple inheritance) are installed under auto-generated getter names `parent2`, `parent3`, ... (SRFI-263 doesn't specify a naming convention for these).

## Implementation notes / interpretive choices

The SRFI's own prose is thin or example-driven in a few places; this implementation's specific choices:

- **Ambiguity detection dedupes by slot identity.** Two different immediate parents that both transitively resolve to the *same* slot (e.g. both eventually reaching `*the-root-object*`'s own `derive` or `message-not-understood`) is not treated as ambiguous — only genuinely different slots from different parents are.
- **`copy`** clones the *receiver's own* slots (not a `parent` slot's slots) — the SRFI's "creates an object with the messages and slots copied from its parent" is read as colloquially describing the object being copied (self), consistent with `copy-object`'s own definition taking an explicit object to copy from.
- Multi-parent auto-naming (`parent2`, `parent3`, ...) as noted above.
- **The parent graph should be acyclic.** `set-parent-slot!` is ordinary public API with no cycle check (the SRFI doesn't specify one), so a buggy or adversarial call — most simply `(obj 'set-parent-slot! 'parent #f obj)` — can create one. Every search that walks parent slots (message dispatch, `resend`'s default path, and the mirror's `has-ancestor`/`full-ancestor-list`/`full-slot-list`) guards against this with a visited-set: an already-visited object is treated as a dead end for that branch rather than recursed into again, so a cycle can't hang or crash the process. If a cycle happens to sever every path back to `*the-root-object*` (e.g. the self-referencing example above), even the fallback `message-not-understood`/`ambiguous-message-send` handlers become unreachable — that case raises a plain Scheme error directly rather than attempting a fallback that would itself be unreachable.
