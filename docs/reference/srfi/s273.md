# `(srfi s273 extensions)` — SRFI-273 Extensions to Data (Type-)Checking

```scheme
(import (srfi 273))   ; or (srfi srfi-273) / (srfi s273 extensions)
```

[SRFI-273](https://srfi.schemers.org/srfi-273/) extends [`(srfi 253)`](s253.md) with an optional `=> (predicate ...)` return-value-checking clause on `lambda-checked`/`case-lambda-checked`/`define-checked`, plus four new forms: `check-impl?`, `define-check`, `declare-checked`, `define-values-checked`.

**Fully backward compatible**: every plain SRFI-253 form (no `=>` clause) expands identically through this library — same `check-arg` calls, no added overhead. `(import (srfi 273))` is a safe drop-in replacement for `(import (srfi 253))` wherever both are otherwise in scope.

**Implementation note**: this library does not `import`-and-`rename` SRFI-253's own macros to delegate to them internally — curry's `rename` import filter doesn't work for `define-syntax` bindings, only plain values ([issue #257](https://github.com/deconstructo/curry/issues/257), found while writing this library). Instead, `lambda-checked`'s argument-checking logic is built directly in this file (structurally identical output to SRFI-253's own, just not literally the same macro invocation), and `case-lambda-checked`'s arity dispatcher is a deliberate verbatim copy of SRFI-253's own dispatcher — chosen specifically to inherit its already-reviewed fix for a real exponential-macro-expansion blowup in clause count (see `lib/curry/modules/srfi/s253/data-checking.scm`'s own header comment), rather than risk reintroducing that bug in a fresh reimplementation.

## `(lambda-checked formals [=> (predicate ...)] body ...)` → *procedure*

With no `=>` clause: identical to [`(srfi 253)`'s `lambda-checked`](s253.md). With `=>`: `body`'s returned value(s) — however many there are — are checked positionally against `predicate ...` (via `call-with-values`) before being returned; a wrong return-value count or a failing predicate raises.

```scheme
(define halve (lambda-checked ((n integer?)) => (integer?) (quotient n 2)))
(halve 10)    ; => 5
(halve "x")   ; raises -- bad argument
(define bad (lambda-checked ((n integer?)) => (string?) (quotient n 2)))
(bad 10)      ; raises -- return value isn't a string

;; multiple return values, checked positionally
(define split (lambda-checked ((n integer?)) => (integer? integer?)
                (values (quotient n 2) (remainder n 2))))
(call-with-values (lambda () (split 7)) list)   ; => (3 1)
```

## `(case-lambda-checked (formals [=> (predicate ...)] body ...) ...)` → *procedure*

Like [`(srfi 253)`'s `case-lambda-checked`](s253.md), extended so any individual clause may carry its own `=>` return-check independently of the others.

```scheme
(define f (case-lambda-checked
  (() 'zero)
  ((x) => (integer?) (* x 1))
  ((x y) (+ x y))))
(f)        ; => zero
(f 5)      ; => 5
(f 3 4)    ; => 7
```

## `(define-checked (name . formals) [=> (predicate ...)] body ...)`
## `(define-checked name predicate value)`

Procedure form extended with the same optional `=>` clause as `lambda-checked`; equivalent to `(define name (lambda-checked formals [=> (predicate ...)] body ...))`. The value form is unchanged from SRFI-253.

```scheme
(define-checked (sq x) => (integer?) (* x x))
(sq 4)   ; => 16
```

## `check-impl?` — auxiliary syntax

An escape hatch usable anywhere a predicate is expected — an argument's check position, or inside a `=> (...)` return-check list — meaning "no check here." curry has no separate static type-checking pass to substitute an implementation-specific check with, so this is simply treated as an always-pass check. **Using it inside `values-checked`** (the plain SRFI-253 form, not `define-values-checked`) **is an error**, per the SRFI text — it's only recognized in the forms listed above.

```scheme
(define f (lambda-checked ((x (check-impl? anything))) => ((check-impl? anything))
            x))
(f "no checking happens on this at all")
```

## `(define-check name predicate)`

Names or aliases a predicate — `(define name predicate)`, matching the SRFI's own reference implementation exactly. Mainly useful for giving a composed/derived predicate a descriptive name.

```scheme
(define-check my-integer? integer?)
(my-integer? 5)   ; => #t
```

The SRFI's own rationale example, `(define-check positive-integer? (conjoin integer? positive?))`, needs [SRFI 235](https://srfi.schemers.org/srfi-235/) (`conjoin`/`disjoin`/`complement`) — **not yet implemented in curry** as of this writing, so that exact example doesn't run as written here. A hand-written combinator (`(lambda (x) (and (integer? x) (positive? x)))`) works today in its place. [SRFI 43](https://srfi.schemers.org/srfi-43/)'s `vector-every` (also named in the SRFI text's non-normative "optimizable check patterns" list) is likewise not yet implemented; [SRFI 1](s1.md)'s `every` and [SRFI 26](s26.md)'s `cut` — the other two patterns that list names — both already exist in curry and work as shown in the SRFI text today.

## `(declare-checked name predicate)`
## `(declare-checked (name args ...) [=> (predicate ...)])`

A genuine no-op here, matching the SRFI's own reference implementation exactly. Both forms parse and evaluate harmlessly, for documentation/forward-declaration purposes (declaring what a procedure defined elsewhere — another module, a C primitive, code not yet written — is expected to accept and return, similar in spirit to a TypeScript `.d.ts` file). **This library does not retrieve or enforce a declared check anywhere** — the SRFI text itself gives no way to read one back; that's the job of [SRFI 283](https://srfi.schemers.org/srfi-283/) (check/type introspection, a separate, not-yet-implemented SRFI), not 273 on its own.

```scheme
(declare-checked (external-sqrt x) => (number?))   ; documentation only
```

## `(define-values-checked (var ...) (predicate ...) form)`

Like `define-values`, except `form`'s returned values are checked positionally against `predicate ...` before binding — a **real** implementation, not the SRFI document's own reference example (which is literally unchecked `define-values`, given there as a minimal conforming placeholder rather than a usable one).

```scheme
(define-values-checked (q r) (integer? integer?) (values (quotient 7 2) (remainder 7 2)))
(list q r)   ; => (3 1)

(define-values-checked (bad) (string?) (values 42))   ; raises
```
