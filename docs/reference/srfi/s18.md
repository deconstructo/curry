# `(srfi s18 multithreading)` — SRFI-18

```scheme
(import (srfi s18 multithreading))
```

[SRFI-18](https://srfi.schemers.org/srfi-18/) threads, layered on curry's actor system (`spawn`/`send!`/`receive`) and `(curry sync)` — curry's only real-thread primitives; `(curry sync)`'s own documentation says as much and intentionally doesn't expose raw `pthread_create`.

## Threads

#### `(make-thread thunk)` → *thread*
#### `(make-thread thunk name)` → *thread*

Create a thread in the *not-yet-started* state (per SRFI-18, threads are created suspended). `name` is purely informational (`thread-name`); omit it and it's `#f`.

#### `(thread? obj)` → *boolean*

#### `(thread-name t)` → *the name given to `make-thread`, or `#f`*

#### `(thread-start! t)` → *t*

Actually spawns the thread (via curry's `spawn`), running `thunk`. Starting an already-started thread is a no-op. Returns `t` itself, so `(thread-start! (make-thread ...))` is a common one-liner.

#### `(thread-join! t)` → *the value `thunk` returned*
#### `(thread-join! t timeout)` → *the value `thunk` returned*

Block until `t` finishes, then return what its thunk returned. **If the thunk raised an uncaught exception, `thread-join!` returns `#f` instead of propagating it or raising** — this is a real deviation from the SRFI (which specifies the join should re-raise, or return a supplied default), and `#f` is indistinguishable from a thunk that legitimately returned `#f`. Don't rely on `thread-join!`'s return value alone to detect thread failure; have the thunk report its own errors (e.g. via `thread-specific-set!`, or a shared mutable cell) if that matters. `timeout`, if given, is accepted but currently has no effect — the wait is unconditional.

```scheme
(define t (thread-start! (make-thread (lambda () (+ 1 2 3)))))
(thread-join! t)  ; => 6

(define t2 (thread-start! (make-thread (lambda () (error "boom")))))
(thread-join! t2)  ; => #f  -- the error is silently lost
```

#### `(thread-sleep! seconds)`

Blocks the calling thread for (at least) `seconds`. Implemented as a timed condition-variable wait on a private, never-signaled mutex/condvar pair — functionally a plain sleep, just riding the same primitive `(curry sync)` uses for everything else.

#### `(thread-yield!)`

`(thread-sleep! 0)`.

#### `(thread-terminate! t)`

**Always raises.** curry's actor threads are detached pthreads with no cancellation hook, so there's no way to implement this; it exists only so a program written against the full SRFI-18 surface fails loudly (with a clear message) rather than silently doing nothing.

#### `(current-thread)` → `#f`

Always `#f` — there's no reified handle for the thread currently running (whether that's the main thread or one spawned some other way).

#### `(thread-specific t)` → *the value most recently set, or `#f`*
#### `(thread-specific-set! t v)`

A single mutable slot attached to `t`, for whatever the caller wants (commonly: a place for a thread to report its own result/status, given `thread-join!`'s exception-swallowing above).

## Timeouts and termination — always `#f`

#### `(join-timeout-exception? obj)` → `#f`
#### `(terminated-thread-exception? obj)` → `#f`

Always `#f`, unconditionally — since `thread-join!`'s `timeout` argument has no effect and `thread-terminate!` always raises a plain error rather than causing a join elsewhere to see a specific timeout/termination exception object, these predicates have nothing to ever recognize.

## Mutexes and condition variables

Re-exports of `(curry sync)`'s own procedures under their SRFI-18 names — see [`../module-sync.md`](../module-sync.md) for the full mutex/condition-variable API these forward to:

- `make-mutex`, `mutex?`, `mutex-lock!`, `mutex-unlock!`
- `make-condition-variable` (= `make-condvar`), `condition-variable?` (= `condvar?`), `condition-variable-signal!` (= `cond-signal!`), `condition-variable-broadcast!` (= `cond-broadcast!`)

```scheme
(define t (thread-start! (make-thread (lambda () (+ 1 2 3)))))
(thread-join! t)  ; => 6
```
