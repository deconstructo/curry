# `(srfi s28 format)` — SRFI-28

```scheme
(import (srfi s28 format))   ; or (srfi 28), or (srfi srfi-28)
```

[SRFI-28](https://srfi.schemers.org/srfi-28/) Basic Format Strings: `(format format-string obj ...)` interprets a template string containing `~`-prefixed directives, substituting each with a stringified argument or literal text.

```scheme
(format "~a is ~a years old.~%" "Ada" 36)
; => "Ada is 36 years old.\n"
```

## Directives

| Directive | Behavior | Consumes an argument? |
|---|---|---|
| `~a` | Insert as `display` would print it | Yes |
| `~s` | Insert as `write` would print it | Yes |
| `~%` | Literal newline | No |
| `~~` | Literal tilde | No |
| `~N@*` | Positional reference (see below) | No (redirects the *next* `~a`/`~s`) |

`~a`/`~s`/`~%`/`~~` are case-insensitive (`~A`, `~S` work identically).

## `~N@*` — positional reference

[SRFI-29](s29.md)'s own extension to this same format engine, included here (not kept SRFI-29-only) since it's just another directive inside an ordinary format string — a template produced by `(srfi 29)`'s `localized-template` is meant to be handed straight to this same `format`, so splitting the directive into a second, separate `format` procedure would make one format string behave differently depending on which library happened to be in scope.

`~N@*` (N a non-negative integer) redirects the *immediately following* `~a` or `~s` to read argument index `N` (zero-based, absolute) instead of the next argument in sequence — and critically, doing so does **not** advance the normal sequential cursor. A plain `~a` right after a `~N@*~a` jump still reads whatever the cursor was already pointing at.

```scheme
(format "~1@*~a, c'est ~a." "fromage" "bon")
; => "bon, c'est fromage."
;    ~1@*~a reads argument 1 ("bon") without touching the cursor;
;    the trailing ~a then reads from the cursor's own position (still 0, "fromage")

(format "~a ~1@*~a ~a" "A" "B" "C")
; => "A B B"
;    first ~a consumes "A" (cursor -> 1); ~1@*~a reads index 1 ("B") without
;    moving the cursor; the trailing ~a consumes the cursor's own position, 1 ("B")
```

## Errors

Per the SRFI's own named error conditions, each of these raises rather than silently misformatting: a trailing bare `~` at the end of the string, an unrecognized directive, too few arguments for a `~a`/`~s`/`~N@*`, and a malformed `~N@*` (missing `@*`, or not followed by `~a`/`~s`).
