# `(srfi s132 sorting)` and `(srfi s133 vectors)` — SRFI-132 / SRFI-133

```scheme
(import (srfi s132 sorting) (srfi s133 vectors))
```

## `(srfi s132 sorting)`

[SRFI-132](https://srfi.schemers.org/srfi-132/). Every sort here is the same stable merge sort — the SRFI permits `list-sort`/`vector-sort` to be unstable, but there's no benefit to a second, less-predictable algorithm, so the "plain" and "stable" names are all aliases of one implementation. `less?` throughout is a strict "less than" predicate (`(less? a b)` true iff `a` sorts strictly before `b`).

An optional trailing `[start [end]]` range (default: the whole vector) is accepted wherever a vector is sorted or checked.

#### `(list-sorted? less? lst)` → *boolean*
#### `(vector-sorted? less? v [start [end]])` → *boolean*

#### `(list-sort less? lst)` → *new list*
#### `(list-stable-sort less? lst)` → *new list* — alias
#### `(list-sort! less? lst)` → *new list* — alias (curry's implementation never mutates `lst` in place regardless of the `!`; it's accepted for interface compatibility)
#### `(list-stable-sort! less? lst)` → *new list* — alias

#### `(vector-sort less? v [start [end]])` → *new vector*
#### `(vector-stable-sort less? v [start [end]])` → *new vector* — alias
#### `(vector-sort! less? v [start [end]])` → *v, sorted in place*
#### `(vector-stable-sort! less? v [start [end]])` → *v, sorted in place* — alias

The `!` vector variants genuinely mutate `v` (unlike the list `!` variants above, which don't); the non-`!` variants copy first and leave `v` untouched.

```scheme
(list-sort < '(3 1 2))  ; => (1 2 3)
```

#### `(list-merge less? a b)` → *new list*
#### `(list-merge! less? a b)` → *new list* — alias (never mutates `a`/`b` in place here)

Merge two already-sorted lists into one sorted list.

#### `(vector-merge less? a b)` → *new vector*

Merge two already-sorted vectors into a freshly-allocated sorted vector.

#### `(vector-merge! less? to a b)` → *to*

Like `vector-merge`, but writes the result into a caller-supplied vector `to` (which must be at least as long as `a` and `b` combined) instead of allocating one — note the different argument shape from the other `!` pairs above (an extra leading `to` argument, not "mutate the first list/vector argument in place").

```scheme
(define to (make-vector 4 0))
(vector-merge! < to #(1 3) #(2 4))
to  ; => #(1 2 3 4)
```

## `(srfi s133 vectors)`

[SRFI-133](https://srfi.schemers.org/srfi-133/) vector extras layered on curry's native R7RS vector ops (`make-vector`, `vector-copy`(`!`), `vector-append`, `vector-map`/`-for-each`, etc., all re-exported unchanged). Like s132, most procedures below accept an optional trailing `[start [end]]` range.

#### `(vector-empty? v)` → *boolean*

#### `(vector= elt=? v ...)` → *boolean*

`#t` iff every `v` has the same length and `elt=?` holds elementwise across all of them. Zero or one vector is trivially `#t`.

#### `(vector-swap! v i j)`

Swap the elements at indices `i` and `j` in place.

#### `(vector-reverse! v [start [end]])` → *v, reversed in place*
#### `(reverse! v)` → *v, reversed in place* — `(vector-reverse! v)`, the whole vector

Note `reverse!` here is the *vector* reverse (this library's own name collides with R7RS's list `reverse!`, which isn't imported alongside it) — don't import this into code that also wants list `reverse!` from elsewhere without renaming one.

#### `(vector-index pred v [start [end]])` → *index or `#f`*
#### `(vector-index-right pred v [start [end]])` → *index or `#f`* — searches from the end

#### `(vector-count pred v [start [end]])` → *exact integer*
#### `(vector-any pred v [start [end]])` → *`pred`'s result on the first match, or `#f`*
#### `(vector-every pred v [start [end]])` → *`pred`'s result on the last element, or `#f`*

```scheme
(vector-index even? #(1 3 4 5))  ; => 2
```

#### `(vector-fold kons knil v [start [end]])` → *value*
#### `(vector-fold-right kons knil v [start [end]])` → *value*

Left/right fold: `(kons acc element)`, threading the accumulator from `knil`.

```scheme
(vector-fold + 0 #(1 2 3 4))  ; => 10
```

#### `(vector-binary-search v key less? [start [end]])` → *index or `#f`*

`v[start,end)` must already be sorted ascending by `less?`. Returns *an* index where `key` is found (not necessarily the first, if there are duplicates), or `#f`.

```scheme
(vector-binary-search #(1 3 5 7 9) 5 <)  ; => 2
```

#### `(vector-concatenate vector-list)` → *new vector*

`(apply vector-append vector-list)`.

#### `(vector-unfold f len seed ...)` → *new vector*
#### `(vector-unfold-right f len seed ...)` → *new vector*

Build a length-`len` vector where element `i` is the first value `f` returns when called as `(f i seed ...)`; any additional values `f` returns become next iteration's `seed ...`. `vector-unfold` iterates `i` from `0` to `len-1`; `vector-unfold-right` iterates from `len-1` down to `0` — for an `f` with no real seed-threading (each call independent of the last) the two produce the same vector, but when `seed ...` genuinely threads state between calls (an accumulator, a generator's next state, …) the two visit indices in opposite order and so can produce different results.

```scheme
(vector-unfold (lambda (i) (* i i)) 5)  ; => #(0 1 4 9 16)

;; seed-threading example where order matters
(vector-unfold       (lambda (i seed) (values (+ seed i) (+ seed i))) 5 100)
; => #(100 101 103 106 110)
(vector-unfold-right (lambda (i seed) (values (+ seed i) (+ seed i))) 5 100)
; => #(110 110 109 107 104)
```
