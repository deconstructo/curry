# `(srfi s210 multiple-values)` — SRFI-210

```scheme
(import (srfi s210 multiple-values))
```

[SRFI-210](https://srfi.schemers.org/srfi-210/): convenience syntax and procedures for multiple-value programming, layered entirely on plain `call-with-values` — application forms that mix single values with a trailing producer's multiple values, chaining/composition helpers ("transducers": procedures that take some values and return some values), and a couple of small utility procedures.

## Application forms

Each of these evaluates its producer (and any operands) and combines the results — the differences are just what shape the combination takes.

#### `(apply/mv operator operand ... producer)`

Calls `operator` with `operand ...` followed by all of `producer`'s values.

```scheme
(apply/mv string #\a (values #\b #\c))  ; => "abc"
```

#### `(call/mv consumer producer ...)`

Calls `consumer` with every value from every producer, concatenated in order — Common Lisp's `multiple-value-call`.

```scheme
(call/mv string (values #\a #\b) (values #\c #\d))  ; => "abcd"
```

#### `(list/mv element ... producer)` / `(vector/mv element ... producer)`

Builds a list/vector from the single-valued `element ...` followed by `producer`'s values.

```scheme
(list/mv 'a (values 'b 'c))    ; => (a b c)
(vector/mv 'a (values 'b 'c))  ; => #(a b c)
```

#### `(box/mv element ... producer)`

Same shape, building an [SRFI-195](s195.md) multiple-value box.

```scheme
(unbox (box/mv 'a (values 'b 'c)))  ; => a, b, c (as 3 values)
```

#### `(value/mv index operand ... producer)`

The `index`-th (0-based) value from `operand ...` followed by `producer`'s values. Raises if `index` isn't an exact non-negative integer in range.

```scheme
(value/mv 1 'a (values 'b 'c))  ; => b
```

#### `(coarity producer)`

The number of values `producer` produces, as an exact integer.

```scheme
(coarity (values 'a 'b 'c))  ; => 3
```

## Binding forms

#### `(set!-values formals producer)`

Like `let-values`' binding clause, but mutates **existing** variables (via `set!`) rather than introducing new ones — same lambda-style `formals` grammar (proper list, dotted rest, or a bare symbol capturing everything).

```scheme
(let ((x #f) (y #f))
  (set!-values (x . y) (values 'a 'b))
  (list x y))  ; => (a (b))
```

#### `(with-values producer consumer)`

`producer` is a plain expression (not a thunk you write yourself) — `with-values` wraps it in one for you before handing off to `call-with-values`.

```scheme
(with-values (values 4 5) (lambda (a b) b))  ; => 5
```

#### `(case-receive producer clause ...)`

Like `case-lambda` for a single set of produced values: evaluates `producer` once, then runs the body of the **first** clause `(formals body ...)` whose `formals` shape accepts that many values. Raises if no clause matches.

```scheme
(case-receive (values 'a 'b)
  ((x) 'one-value)
  ((x . y) (list x y)))  ; => (a (b))
```

## Chaining ("transducers")

A *transducer* here just means: a procedure taking some values and returning some values (via plain `values`) — not related to the fold-based "transducer" idiom from other languages.

#### `(bind/mv producer transducer ...)`

Chains `transducer ...` left to right, starting from `producer`'s values: `transducer1` gets `producer`'s values, `transducer2` gets `transducer1`'s result, and so on.

```scheme
(bind/mv (values 1 2 3)
         (map-values (lambda (x) (* 2 x)))
         (map-values (lambda (x) (+ 1 x))))
; => 3, 5, 7 (as 3 values)
```

#### `(compose-left transducer ...)` / `(compose-right transducer ...)` → *procedure*

Builds a single procedure chaining the given transducers left-to-right or right-to-left; unlike `bind/mv`, there's no producer here — the returned procedure's own arguments are what the first (or last, for `compose-right`) transducer receives.

```scheme
(define f (map-values (lambda (x) (* 2 x))))
(define g (map-values (lambda (x) (+ x 1))))
(call-with-values (lambda () ((compose-left f g) 1 2 3)) list)   ; => (3 5 7)
(call-with-values (lambda () ((compose-right f g) 1 2 3)) list)  ; => (4 6 8)
```

#### `(map-values proc)` → *procedure*

Returns a procedure that applies `proc` to each of its arguments independently, yielding all the results as multiple values — the single-values-in, single-values-out building block `bind/mv`/`compose-left`/`compose-right` are typically chained with.

```scheme
((map-values odd?) 1 2 3)  ; => #t, #f, #t
```

#### `(bind/list list transducer ...)` / `(bind/box box transducer ...)` / `(bind obj transducer ...)`

Like `bind/mv`, but starting from a list's elements, an [SRFI-195](s195.md) box's contents, or a single object, instead of an already-multi-valued producer expression.

```scheme
(bind/list '(1 2 3) (map-values (lambda (x) (* 3 x))))  ; => 3, 6, 9
(bind 1 (lambda (x) (values (* 3 x) (+ 1 x))))          ; => 3, 2
```

## Procedures

#### `(list-values list)` / `(vector-values vec)` / `(box-values box)`

Yields a list's elements, a vector's elements, or a box's contents (equivalent to `unbox`) as multiple values. Each raises if given the wrong type.

#### `(value index obj ...)`

The `index`-th (0-based) argument. Raises if `index` isn't an exact non-negative integer less than the argument count.

```scheme
(value 1 'a 'b 'c)  ; => b
```

#### `(identity obj ...)`

Returns its arguments unchanged, as multiple values — equivalent to `values` itself, useful as a default/no-op transducer.

## Known limitation: no proper tail calls through `call-with-values`

Every form here is built on `call-with-values`, and curry's own `call-with-values` primitive invokes its consumer through a real (nested) C call rather than a genuine bytecode-level tail call — the same gap [`(srfi s64 testing)`](s64.md)'s `receive` already has. Any of these forms placed in the tail position of a self-recursive loop will eventually hit curry's call-stack limit rather than looping forever; this is a VM-level gap tracked separately, not something specific to this library. A zero-value producer (`(values)`) fed into `call-with-values` also currently fails outright — also pre-existing, also tracked separately — so `coarity`/`bind/mv`/etc. can't be used with a producer that yields exactly zero values yet.
