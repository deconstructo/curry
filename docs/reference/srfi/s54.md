# `(srfi s54 cat)` — SRFI-54

```scheme
(import (srfi s54 cat))
```

[SRFI-54](https://srfi.schemers.org/srfi-54/): `cat` converts any object to a string, with optional formatting arguments accepted **in any order** — each is recognized purely by its own shape (a symbol, a character, a list starting with a procedure, and so on), not by position.

```scheme
(cat obj arg ...)
```

This SRFI is unusually large and, for numbers, its optional arguments interact in some genuinely exotic ways. This implementation covers every non-number argument fully, and every number argument for **real numbers in decimal radix** fully; non-decimal radix is supported for **exact integers only**. A few of the spec's own more exotic worked examples (a non-decimal radix combined with an inexact number, precision applied to a complex number) are out of scope — see [Known limitations](#known-limitations) below.

## How arguments are recognized

| Shape | Meaning | Applies to |
|---|---|---|
| `exact` / `inexact` | force the number's exactness | numbers only |
| `binary` / `octal` / `decimal` / `hexadecimal` | radix (default `decimal`) | numbers only |
| `sign` | force a `+` on a positive number | numbers only |
| an inexact integer, e.g. `2.` | precision: digits after the decimal point | numbers only |
| a list `(char [n])` | separator: group every `n` chars with `char` (default `n` = 3) | numbers only |
| a procedure of 2 args `(obj port)` | writer: how to render `obj` | non-numbers only |
| a list of procedures `(proc ...)` | pipe: each takes a string, returns a string, chained left-to-right | non-numbers only |
| a list `(n [m])` of exact integers | take: `n` chars from the left, `m` from the right (negative = "all but \|n\|"), concatenated | non-numbers only |
| a pair `(predicate . converter)` | if `(predicate obj)`, use `(converter obj)` as the string outright | any type |
| an exact integer | width: \|width\| is the field width; negative left-aligns | any type |
| a character | padding character (default space) | any type |
| a string | appended to the result, in the order given (may appear more than once) | any type |
| `#f` / `#t` / a port | where to also write the result (`#f`: nowhere, the default) | any type |

## Numbers

Processing order: **exactness → radix → precision → separator → sign**.

```scheme
(cat 129.995 -10 2.)              ; => "130.00    "   (precision 2, width 10 left-aligned)
(cat 129 2.)                      ; => "#e129.00"     (exact + non-negative precision => #e prefix)
(cat 129 -2.)                     ; => "129.00"        (negative precision => no #e prefix)
(cat 129 10 2. #\0 'sign)         ; => "#e+0129.00"   (zero-pad goes AFTER the sign/#e run)
(cat 129 10 2. #\* 'sign)         ; => "*#e+129.00"   (any other pad char goes at the edge)
(cat 1/3 10 2.)                   ; => "    #e0.33"
(cat 129.995 10 '(#\, 2))         ; => " 1,29.99,5"   (grouped outward from the decimal point)
(cat 129995 10 '(#\,) 'sign)      ; => "  +129,995"   (default group size 3)
(cat #x123 'octal 'sign)          ; => "#o+443"
```

Precision rounds using the number's own printed decimal form (round-half-to-even), not its raw binary value — `129.985` rounds to `129.98`, matching what the digits actually written say, even though `129.985`'s true double value sits a hair above the halfway point.

Combining a non-decimal radix with `precision`, or with anything besides an exact integer, raises — the spec itself calls this combination out as an error ("non-decimal cannot have a decimal point").

## Non-numbers

```scheme
(cat "string" -10)                             ; => "string    "
(cat "string" 10 (list string-upcase))         ; => "    STRING"
(cat "string" 10 (list string-upcase) '(-2))   ; => "      RING"   (drop 2 from the left after upcasing)
(cat #\a 10)                                   ; => "         a"
(cat '(#\a "str" s))                           ; => "(#\\a \"str\" s)"
```

The default writer is `display` when `obj` is a self-evaluating constant (number, string, character, boolean), and `write` otherwise (symbols, pairs, vectors, …) — matching how those print at a REPL without an explicit `quote`.

## Appending strings and writing to a port

```scheme
(cat 129 "-" (cat "str"))          ; => "129-str"
(cat 3 (cat 's) " " (cat "str" write))  ; => "3s \"str\""
```

A bare `#t` writes the result to `(current-output-port)` (in addition to returning it); a port object writes there instead; `#f` (the default) has no side effect.

## Converter

```scheme
(define (example? x) (and (pair? x) (eq? (car x) 'ex)))
(define (record->string x) (string-append (number->string (cadr x)) "-" (caddr x)))

(cat (list 'ex 123 "string") 20 (cons example? record->string))
; => "          123-string"
```

When `(predicate obj)` is true, `(converter obj)` becomes the object's string directly — `writer`/`pipe`/`take` never run — and only `width`/`char`/`port`/`string` still apply on top of it. If the predicate is false, `cat` falls back to normal (number vs. non-number) formatting.

## Known limitations

- **Non-decimal radix** is only implemented for exact integers. Combining `binary`/`octal`/`hexadecimal` with an inexact number or a non-integer raises, rather than attempting the spec's own dual-prefix behavior for that case (e.g. `"#i#o+307/2"`).
- **`precision` on a complex number** (real and imaginary parts formatted independently) isn't implemented.
- Precision rounding for an **inexact** number is limited by curry's own `number->string`, which doesn't currently round-trip every flonum losslessly (a separate, pre-existing gap) — a number whose shortest-round-trip decimal string has more digits than curry actually prints may round slightly differently than a fully faithful implementation would.
