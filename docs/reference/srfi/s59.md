# `(srfi s59 vicinity)` — SRFI-59 vicinity

```scheme
(import (srfi s59 vicinity))
```

[SRFI-59](https://srfi.schemers.org/srfi-59/): a *vicinity* is a directory path string, always ending in the separator character (`vicinity:suffix?`, `#\/` here). This library predates R7RS module search paths — think of it as "the directory a path lives in," used to build a second path relative to the first.

Unix-only, matching curry's own Linux/macOS build targets: the separator is always `#\/`.

#### `(pathname->vicinity path)` → *string*
#### `(->vicinity path)` → *string*

The directory portion of `path`, including the trailing separator. Same procedure under two names (`->vicinity` is an alias). If `path` has no separator, returns `""`.

```scheme
(pathname->vicinity "/a/b/c.scm")  ; => "/a/b/"
(pathname->vicinity "c.scm")       ; => ""
```

#### `(vicinity:suffix? char)` → *boolean*

`#t` iff `char` is the vicinity separator (`#\/`).

#### `(make-vicinity path)` → *string*

`path` with a trailing separator appended if it doesn't already have one.

```scheme
(make-vicinity "/a/b")   ; => "/a/b/"
(make-vicinity "/a/b/")  ; => "/a/b/"
```

#### `(->namestring vicinity)` → *string*

Identity — returns `vicinity` unchanged. (SRFI-59 defines this for implementations whose internal vicinity representation isn't already a plain string; curry's already is.)

#### `(in-vicinity vicinity name)` → *string*

`vicinity` and `name` concatenated directly (no separator inserted — `vicinity` is expected to already end in one).

```scheme
(in-vicinity "/a/b/" "c.scm")  ; => "/a/b/c.scm"
```

#### `(sub-vicinity vicinity name)` → *string*

Like `in-vicinity`, but the result is itself passed through `make-vicinity` — use this to descend into a subdirectory rather than name a file.

```scheme
(sub-vicinity "/a/b/" "c")  ; => "/a/b/c/"
```

#### `(program-vicinity)` → *string*

The directory of the currently running script, derived from `(command-line)`'s first element. `"./"` if `(command-line)` is empty or its first element is an empty string (e.g. the REPL with no script argument).

#### `(library-vicinity)` → *string*
#### `(implementation-vicinity)` → *string*

Both are best-effort fallbacks to `(program-vicinity)`: neither `CURRY_MODULE_PATH`'s search-path list nor curry's install prefix is introspectable from Scheme, so there's no more precise answer available.

#### `(home-vicinity)` → *string or `#f`*

`(make-vicinity (get-environment-variable "HOME"))`, or `#f` if `$HOME` isn't set.

#### `(user-vicinity)` → *string*

Always `""` (curry has no per-user library search path distinct from `CURRY_MODULE_PATH`, which is process-global).
