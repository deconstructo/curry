# `(srfi s78 lightweight-testing)` — SRFI-78 Lightweight Testing

```scheme
(import (srfi s78 lightweight-testing))
```

[SRFI-78](https://srfi.schemers.org/srfi-78/): a minimal inline testing mechanism built around the `check` macro, with global pass/fail counters and a report.

`check-ec` (the [SRFI-42](https://srfi.schemers.org/srfi-42/) eager-comprehension variant, for parametric test sequences) is **not implemented** — curry has no SRFI-42, and `check-ec` is purely a convenience layer over repeated `check` calls, not new checking logic of its own. Everything else in the spec is implemented.

#### `(check expr => expected)` — *syntax*

Evaluates `expected` (and, when given, the custom equality predicate) before `expr`, compares the two with `equal?`, and records/reports the result per the current mode. In the default `'report` mode, **every** check prints, pass or fail — not just failures:

```scheme
(check (+ 1 1) => 2)   ; prints: (+ 1 1) => 2 ; correct
(check (+ 1 1) => 3)   ; fails and prints:
                       ;   (+ 1 1) => 2 ; *** failed ***
                       ;   ; expected result: 3
```

#### `(check expr (=> equal) expected)` — *syntax*

Same, but compares with `equal` instead of `equal?`.

```scheme
(check (+ 1 1) (=> =) 2.0)   ; passes -- compared with = instead of equal?
```

#### `(check-set-mode! mode)` — *procedure*

Matches the reference implementation's actual semantics (fetched from the SRFI's own `check.scm`), which differ from a literal prose reading in one important way: `'off` doesn't just suppress output, it means `expr` is **never evaluated at all** (wrapped in a thunk that's simply never called) and the check isn't counted either — the same as `assert`-disabling in other languages, not a "silent but still counted" mode.

| mode | evaluates & counts? | prints per-check |
|------|---------------------|-------------------|
| `'report` (default) | yes | every check, pass or fail |
| `'report-failed` | yes | failures only |
| `'summary` | yes | nothing (only `check-report`'s summary) |
| `'off` | **no** — `expr` never runs | nothing |

If you want checks counted but not printed inline, use `'summary`, not `'off`.

#### `(check-reset!)` — *procedure*

Resets the pass/fail counters and the mode back to `'report` — the same state as immediately after importing the library. Note: this resets the mode too, so call `check-set-mode!` **after** `check-reset!` if you want a non-default mode for what follows, not before.

#### `(check-passed? expected-total-count)` → boolean — *procedure*

`#t` if no check has failed and exactly `expected-total-count` checks have run since the last reset. Meant for a script's own exit-code decision:

```scheme
(check (+ 1 1) => 2)
(check (* 2 3) => 6)
(exit (if (check-passed? 2) 0 1))
```

#### `(check-report)` — *procedure*

Prints the first failure (if any) again, plus a `N out of M checks passed` summary line. No-op in `'off` mode.
