# `(srfi 166 ...)` — SRFI-166 Monadic Formatting

```scheme
(import (srfi 166))              ; everything below
(import (srfi 166 base))         ; show, each, fn, with, numbers, padding, trimming, state variables
(import (srfi 166 pretty))       ; pretty, pretty-shared, pretty-simply, pretty-with-color
(import (srfi 166 columnar))     ; columnar, tabular, wrapped, justified, from-file, line-numbers
(import (srfi 166 unicode))      ; terminal-aware, terminal widths, upcased, downcased
(import (srfi 166 color))        ; as-red, on-blue, as-bold, as-color, ...
(import (srfi 272 show))         ; pprinted: the SRFI-272 pretty printer as a formatter
```

Each library can also be imported as `(srfi srfi-166 ...)`.

[SRFI-166](https://srfi.schemers.org/srfi-166/) (Alex Shinn, Final 2020, replaces SRFI-159) is a library for building formatted text from parts. It is an alternative to `format` and to printf-style templates.

```scheme
(import (scheme base) (srfi 166))
(show #f "total: " (padded 8 (numeric/comma 1234567.5 3 10 2)) nl)  ; => "total: 1,234,567.50\n"
(show #t (columnar 12 (displayed "name\nada\n") 8 'right (displayed "age\n36\n")))
```

## The model

A **formatter** is a value that writes text when `show` applies it. You build formatters from other formatters with `each`, `joined`, `padded` and the rest. A string or character where a formatter is expected means `displayed`; any other object is written with the `writer` state variable (by default `written`).

A **state variable** holds a setting such as the current column, the radix, or the padding character. `fn` reads state variables, `with` changes them for the length of some formatters (like `parameterize`), and `with!` changes them for the rest of the sequence.

```scheme
(show #f "column: " (fn (col) col))                       ; => "column: 8"
(show #f (with ((radix 16)) 255))                         ; => "ff"
(show #f (with ((precision 2)) (acos -1)))                ; => "3.14"
```

`fn` binds names to state variables: `(fn ((c col) (r row)) ...)`, or `(fn (col) ...)` when the name is the variable's name. The last form of its body is the formatter it returns. Make your own variable with `(make-state-variable "name" default)`.

State variables: `port`, `row`, `col`, `width` (default 78), `output`, `writer`, `string-width`, `substring/width`, `substring/preserve`, `pad-char`, `ellipsis`, `radix`, `precision`, `decimal-sep`, `decimal-align`, `sign-rule`, `comma-rule`, `comma-sep`, `word-separator?`, `ambiguous-is-wide?`, `pretty-environment`.

## Differences from the reference implementation

- **No re-entrant continuations.** `columnar` and `trimmed/lazy` use first-class continuations in the reference implementation; curry's `call/cc` only escapes. A column here runs to completion into a string. A column marked `'infinite` (such as `(line-numbers)`) runs after the finite ones and stops by escaping from its own output once it has as many lines as the longest finite column. `trimmed/lazy` stops the same way once the output is wider than its limit. The results are the same.
- **`forked`.** The SRFI does not say whether the first formatter's output appears. Here it does, and so does the row and column it reached; only the state variables it changed are put back before the second formatter runs.
- **`maybe-escaped`.** The SRFI's third example of `maybe-escaped` shows the quote characters inside the string left unescaped. This port escapes them with `escape-ch`, exactly as `escaped` does.
- **`string-width` default.** It counts characters, as the SRFI says. ANSI sequences from the color formatters therefore count as characters too; wrap padded or trimmed colored text in `terminal-aware`.
- **Rounding.** `precision` rounds ties to even (`2.5` with precision 0 is `2`, `1.5` is `2`), in exact arithmetic, so `(with ((precision 20)) 1/7)` is exact.
- **`decimal-align`.** Pads the integer part on the left, with `pad-char`, to at least that many columns.
- **`pretty`.** The SRFI gives no layout rules. `pretty`, `pretty-shared`, `pretty-simply` and `pretty-with-color` use the [SRFI-272](s272.md) layout, starting at the current column with later lines indented to it. `pretty-with-color` gives color even when the terminal was not detected.
- **Numbers inside structures.** `written` formats every number in a list or vector with the current `radix` and `precision`.

## Unicode and cuneiform

Widths are terminal columns (UAX #11, Unicode 16.0, the same tables as SRFI-272): wide and fullwidth characters and emoji take 2, nonspacing marks and format characters 0, everything else 1. **Cuneiform signs take 1 column each**, and so do the Akkadian transliteration letters (`š ṭ ḫ ā ī`), precomposed or as base letter plus combining mark.

`string-terminal-width/wide` and the `/wide` substring variants count East Asian Ambiguous characters (Greek, Cyrillic, many symbols) as 2; `terminal-aware` picks them when `ambiguous-is-wide?` is true. ANSI escape sequences take no columns.

`substring-terminal-width` never splits a cluster (a base character with its marks, a ZWJ emoji sequence, a flag). As the SRFI's examples show, a wide character that straddles the start column is included, so the piece can be wider than `to - from`; `trimmed` moves the start to the right until the piece fits, so trimmed text is never wider than asked for.

`downcased` applies the Greek final-sigma rule (`"ΜΈΛΟΣ"` becomes `"μέλος"`). Both `upcased` and `downcased` leave ANSI sequences alone. They use curry's character case mappings, which are one-to-one: `(upcased "straße")` gives `"STRAßE"` (issue #355).

Text is written exactly as given, so cuneiform and Akkadian symbols and strings are not escaped by `written` or `displayed`.

## `columnar` and friends

`(columnar column ...)` — each column is a formatter or a string. A bare string is a border, repeated on every line. Before a formatter you can put a width (a positive integer, or a real between 0 and 1 for a fraction of what the fixed columns leave), a justification (`'left`, `'right`, `'center`), and `'infinite`. Columns with no width share the rest evenly, the extra columns going to the leftmost: 78 columns over 5 gives 16, 16, 16, 15, 15. All columns except the last are padded on the right.

`(tabular column ...)` is the same but sizes each unspecified column to its longest line.

`wrapped`, `justified` and `wrapped/list` break text into lines of `width` columns, minimizing the sum of the cubes of each line's trailing space (the last line is free), as `fmt(1)` does. `justified` also spreads the spaces so lines are flush on the right, the extra spaces going to the left gaps. `wrapped/char` breaks at the width wherever it falls. A word longer than the width gets a line of its own.

## `(srfi 272 show)`

```scheme
(import (scheme base) (srfi 166) (prefix (srfi 272 show) ps:))
(show #t (with ((width 40)) (ps:pprinted '(define (f x) (g x) (h x)) 'pp-level 3)) nl)
```

`pprinted` is like `pretty` but takes the keyword arguments of the advanced tier; `pprinted*` takes a final list of keys and values. The `width` state variable overrides `pp-width`. Neither writes a trailing newline.
