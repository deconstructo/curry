# `(srfi s212 aliases)` — SRFI-212 Aliases

```scheme
(import (srfi s212 aliases))
```

[SRFI-212](https://srfi.schemers.org/srfi-212/): `define-alias` makes one identifier name the same binding as another.

#### `(define-alias new old)` — *syntax*

```scheme
(define (original-name x) (* x 2))
(define-alias alias-name original-name)

(alias-name 21)              ; => 42
(map alias-name (list 1 2 3)) ; => (2 4 6)
```

Works generically — as a bare reference or applied — for any ordinary value `old` is bound to (a procedure, a number, anything `define` can bind). This covers the overwhelming majority of real aliasing use: giving a synonym to an existing procedure, the same shape curry's own Akkadian names already use throughout the language.

**Limitation: cannot alias a macro or a hardcoded special form.** curry's macro system is `syntax-rules` only — no `syntax-case`/`er-macro-transformer` reflection — so there is no portable way for `define-alias` to detect "is `old` bound to a macro rather than a value" and branch accordingly. This is the same wall SRFI-61 (a more general `cond` clause, not implemented — see [issue #81](https://github.com/deconstructo/curry/issues/81)) hit trying to override `cond` itself: a `define-syntax`/`define` inside a library body can't reach in and alias one of curry's ~40 hardcoded special forms (`cond`, `lambda`, `define-record-type`, `let`, ...) — those are dispatched directly by the evaluator/compiler on symbol identity, not resolved through macro or environment lookup.

If `old` is a `syntax-rules` macro you wrote yourself (not a core special form), write a forwarding macro by hand instead:

```scheme
(define-syntax new-name
  (syntax-rules ()
    ((_ . args) (old-macro-name . args))))
```
